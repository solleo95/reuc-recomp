# DirectX Renderers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Fully working DirectX 11 and DirectX 12 backends with Vulkan-equivalent visuals and measured performance.

**Architecture:** Share GX command processing and shader algorithms. Keep API device/resource/presentation code in separate native backends. Retain Vulkan as the reference and default.

**Tech Stack:** C++20, SDL3, Slang, Direct3D 11/12, DXGI, existing vendor SDKs, CMake/Ninja, uctest.

**Spec:** `docs/superpowers/specs/2026-10-27-directx-design.md`

## Global Constraints

- Preserve existing `renderer/late_aim.h` and `tests/test_late_aim.cpp` changes.
- No commits or pushes without explicit request.
- Live game checks use uctest, isolated saves, mute, 1280x720 window, unlocked FPS.
- GPU retirement controls packet completion; hidden and rollback draws retain GX side effects.
- Backend/feature failures are explicit. Intermediate functionality does not satisfy full parity.
- Work in the existing requested feature branch; retain the current build and data directories.

## Review Focus

- Invalid or stale backend settings must fail safely without changing unrelated configuration (Task 1).
- Minimized/zero-size windows and resize during in-flight work must preserve ownership and avoid freed resources (Tasks 3/4).
- EFB reads after suppressed presentations and scene replay must preserve content and completion order (Tasks 3/4).
- Resource binding/coordinate differences must not invert images, corrupt skinning, or break depth/alpha (Tasks 2/3/4).
- Unsupported vendor features or missing runtime DLLs must not masquerade as enabled effects (Task 6).
