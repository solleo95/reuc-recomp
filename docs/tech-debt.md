# Tech debt register

Project goal: maximum nativity and performance. Anything that behaves like emulation, or is a stopgap that trades fidelity or speed for progress, is listed here with its native replacement. Newest entries at the bottom of each section. An entry is added in the same step that introduces the stopgap (rule in `docs/superpowers/plans/2026-10-12-runtime-hle.md`, Global Constraints).

Entry format: `TD-nnn` — what it imitates or compromises; why it exists; native replacement; trigger (when to fix); status.

## A. Emulation-like (hardware behaviour imitated instead of native code)

- **TD-047 — Fog range adjustment and exact fog arithmetic.** Native fog comes from the replaced GXSetFog call (80287DC4, words byte-identical to the SDK and verified against the Dolphin train capture) and is applied (A/B/C, projection, fsel, colour) in the pixel shader using the fragment's 24-bit depth. GXSetFogRangeAdj (BP 0xE8 and the 0xE9..0xED table, written live in the train) is not applied, and the fog term uses float math instead of the hardware's fixed-point steps. Replace: decode the range table and apply the x-dependent adjustment; match hardware rounding with a fixture. Trigger: visible fog banding at screen edges or a Dolphin same-frame mismatch.
- **TD-044 — Native TEV arithmetic/material parity.** Fixed NW4R TEV assets are imported by verified field offsets; Vulkan pipeline specialization constants select compiled stage operations, textures, swaps and konst values. No generic FIFO/list command execution. Current shader uses normalized floating-point arithmetic rather than exact GX fixed-point rounding; native UV generation covers UV source/matrices, while normal/position/post generators, lighting channel distinctions, depth/cull/fog and indirect texture operations still need verified implementation (TD-036). Replace: exact native integer stage arithmetic and complete typed material inputs, tested against hand-calculated fixtures. Status: initial two-texture/alpha-mask GPU regression passed; real title/scene parity under verification.

- **TD-043 — Locked-cache transfer timing.** LCLoadBlocks/LCStoreBlocks now perform verified32-byte-block native memmove at SDK call level; locked region is plain allocated RAM, with checked source/destination spans. Source count0 means128blocks. No DMA register model. Transfers complete synchronously; translated queue/wait wrappers observe an empty queue. Replace: native jobs/fences only if actual concurrent transfer semantics matter. Status: real memory effects restored; asynchronous timing parity remains unverified.

- **TD-042 — Native AX audio fidelity and clock control.** SDK calls now drive a native96-sample/3ms stereo mixer with PCM8/PCM16/DSP-ADPCM data decoding, real source cursor/loop/envelope/volume updates, and SDL-owned PCM output. No DSP microcode or mail command execution. Initial replacement implements mainL/R and nearest resampling;4-tap SRC, AUX/reverb/filters, initial delay, surround/remote and depop remain incomplete. Dropped audio periods were corrected: delayed safe points now service each due PCM block, and native mesh boundaries service pending events. A30ms-stall regression verifies at least10blocks. Output queue is still capped100ms by clearing overruns; long pauses/CPU overload and device drift need explicit clock control. Replace: complete verified native effects/resampling and audio-device-clock pacing with bounded drift compensation; preserve actual callbacks and stream positions. Status: provisional; owner confirms music/movie output but reports gameplay stutter; acceptance of the cadence fix remains pending (2026-10-13).

- **TD-010 — EXI bus has no devices.** `EXIImm/EXIDma/EXIImmEx/EXISync/EXISelect/EXILock/...` are replaced at call level (`runtime/hle/exi.cpp`): reads return zeros, `EXIGetID`/`EXIAttach`/`__EXIProbe` report no device. Completion callbacks passed to `EXIImm`/`EXIDma` and the unlock callback of `EXILock` are never called. Consequences: SRAM always comes back invalid (the SDK writes defaults), no RTC, no memory card, no IPL font. Why: a handshake-capable EXI model would be a device emulation. Replace: native services behind the same call boundary (SRAM and settings from a host file, save data on the host file system). Trigger: first game code that needs SRAM values, saves or fonts.
- **TD-011 — DSP boot compatibility handshake remains.** `__OSInitAudioSystem`, `DSPInit` and `__AI_SRC_INIT` are native no-ops; `DSPAddTask` answers its init callback in interrupt context. AI/DSP registers remain plain read-back values. Native AX frame production now mixes actual PCM/ADPCM data and outputs SDL-owned audio (G13); sound/movie playback confirmed by owner. Replace remaining boot/task handshake scaffolding with verified native subsystem initialization. No DSP microcode runs. Fidelity/pacing and missing SFX tracked TD-042.
- **TD-012 — Remaining IOS devices absent.** The generic `IOS_*` interface (`runtime/hle/ios.cpp`) still reports missing devices/invalid descriptors. Native NANDInit and verified ISFS calls now use real Windows files under exe_dir()/saves (G10); no IOS device or ioctl interpreter introduced. The startup check reaches the real missing-save/create-data dialog. Remaining gaps: SYSCONF, Bluetooth/Wii Remote, USB, network, and unimplemented NAND/ISFS calls outside the verified subset. Replace: native host services at each required SDK boundary. Trigger: the first call the game depends on; full in-game save/load acceptance still requires native input.
- **TD-013 — Remaining controller services absent.** Native mouse now feeds verified KPADRead/WPADProbe boundaries for player1: raw deltas, pointer validity and real A button edges; other players remain disconnected. KPADInit/KPADEnableMotor still skip Bluetooth/haptic setup. Remaining callbacks, motion actions, configurable button bindings and gamepad support are unimplemented. Replace: native host action/controller services at verified game/SDK boundaries, with actual input and completion. Trigger: a caller requiring another action or controller service; full gameplay/input latency acceptance. Status: partial, G11; no Bluetooth device model introduced.
- **TD-041 — Neutral motion fields in mouse samples.** Mouse-derived KPAD samples expose constant gravity/horizon/distance fields because the host mouse has no IMU or sensor bar. This is an observable compatibility answer and is recorded as emulation-like debt. Replace: verified native game-level pointer/actions that need no invented motion metadata; map required gestures to real host actions. Trigger: first motion-dependent gameplay or calibration call. Status: open; mouse pointer/A edges are real host input and do not run SDK smoothing. Multiplayer/extensions remain absent under TD-013.
- **TD-014 — GX state/copies/materials remain incomplete.** Native GXBegin/SetArray capture descriptor-sized vertex data; GXDrawDone/SetDrawDone/WaitDrawDone use real Vulkan completion. Native Begin/End resource recording owns checked guest bytes and typed host geometry/array/child data without a hardware cursor model. GXCallDisplayList imports these generated resources into owned DrawPackets, reads current indexed arrays and resolves current child revisions; unknown/prebuilt or externally modified lists stop explicitly. Raw state/indexed-XF bytes outside typed boundaries remain discarded/counted. GPU position/projection transforms, persistent native EFB copy-before-clear and owned map0 texture sampling now work. Full TEV/depth/copy semantics and texture routing remain pending (TD-034/036). Headless diagnostics submits no GPU work and leaves graphics waits pending. Why: staged renderer bring-up; no FIFO/list opcode interpreter introduced. Replace: verified call-level state/material/copy boundaries and native prebuilt/inlined resource imports. Trigger: renderer tasks3/5/6/7. Status: open; G7 confirms a recognizable Nintendo wrist-strap startup card; menu/gameplay and scene parity remain pending.
- **TD-017 — VI hardware state is not modelled.** The retrace is a host timer; the SDK retrace handler is replaced (`__VIInit`), so VI status registers (current line, field) read as constants. The retrace count and the pre/post callbacks live in the SDK globals and are driven by the HLE. Replace: expose scan-line/field from the presentation clock when the renderer exists. Trigger: game code that polls `VIGetCurrentLine` or the field.
- **TD-018 — DVD errors and drive state.** Only END, BUSY, CANCELED and FATAL (failed read) are reported; the drive never reports cover-open, retry or wrong-disc states, and `DVDGetDriveStatus` is translated code over untouched state. Replace: native file service with explicit error injection (missing file) mapped to the SDK states. Trigger: the first game path that reacts to a drive error.

- **TD-033 — Position rows repeated in GPU vertex stream.** Native position/projection math executes on GPU;72-byte vertices include48bytes of selected matrix rows plus UV0 so one draw supports multiple position matrices with64-byte projection push constants. - **TD-004 — Guest registers live in the `Ctx` struct, not in host registers/locals.** Every instruction loads and stores through memory. Replace: register caching in locals per function, spilled around calls (spec §5). Trigger: first performance measurement of the running game.
- **TD-005 — Every guest memory access tests the MMIO window.** One predicted compare per access. Replace: constant-propagate known MMIO bases (`lis 0xCC01`) in the translator and use direct access elsewhere. Trigger: profile shows it.
