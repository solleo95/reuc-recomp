## Что такое хук

Игра состоит из тысяч функций. **Хук** присоединяет вашу функцию к одной из них. Игра вызывает свою функцию как обычно, а непосредственно перед ней, после неё или вместо неё вызывает и вашу. Вы получаете **аргументы** функции (регистры PowerPC `r3`-`r10` и `f1`-`f8`), и всё, что вы там меняете, возвращается в игру.

Хуки принимают только функции из **списка хукаемых функций**. В каждой есть точка хука, встроенная в игру; в остальных местах кода хука нет совсем, поэтому моды не могут замедлить игру.

## Когда использовать хук

По возможности используйте обычный API: `uc.player(1).magazine = 15` проще и безопаснее любого хука. Хук нужен, когда:

- игра принимает решение внутри функции, которое вы хотите отменить или изменить (например, «может ли это оружие стрелять в этом шаге»);
- нужно увидеть **аргументы** вызова, о котором не сообщает ни одно событие;
- вы хотите **заменить** то, что делает функция.

Хукам нужен `"touches_gameplay": true` в `mod.json`.

## Быстрый старт

Запретим игроку 1 стрелять, пока удерживается кнопка «минус»:

```lua
hook.pre('GameWeaponUpdate', function(regs)
  if uc.input.held & 0x10 ~= 0 then     -- кнопка «минус»
    regs.r4 = 0                         -- «стрельба в этом шаге не разрешена»
  end
end)
```

```js
hook.pre('GameWeaponUpdate', (regs) => {
  if (uc.input.held & 0x10) regs.r4 = 0;
});
```

`regs.r4` - флаг «разрешено» у `GameWeaponUpdate`; его сброс останавливает стрельбу при зажатом курке (проверено в игре).

## Регистры

Соглашение о вызовах PowerPC передаёт первые аргументы в регистрах. Колбэк хука получает таблицу `regs`:

| Поле | Смысл |
|---|---|
| `regs.r3` ... `regs.r10` | Целочисленные аргументы, как целые числа. Указатели - **гостевые адреса** (`0x80...`). |
| `regs.f1` ... `regs.f8` | Аргументы с плавающей запятой, как числа. |

То, что вы присвоите этим полям, **записывается обратно до выполнения функции игры**; регистры, которых вы не трогали, остаются как были. Колбэк, вызвавший ошибку или не уложившийся во время, ничего не меняет.

Значения записываются обратно **как есть**. Порт их не проверяет. Регистр с адресом, которому присвоили неверный адрес, или число, установленное в NaN, может уронить игру или испортить её состояние, как и неверный `uc.mem.write_*`. Меняйте только то, что понимаете, и только нужные регистры.

`r3` - ещё и то место, где передаётся **возвращаемое значение** функции (а `f1` - для дробных).

## Три вида хуков

```lua
hook.pre('GameWeaponUpdate', function(regs) ... end)       -- до функции
hook.replace('GameWeaponUpdate', function(regs) ... end)   -- вместо функции
hook.post('GameWeaponUpdate', function(regs) ... end)      -- после функции
```

| Вид | Когда выполняется | Что можно сделать |
|---|---|---|
| `hook.pre(name, fn)` | Перед телом функции | Посмотреть и изменить аргументы. |
| `hook.replace(name, fn)` | Вместо тела | Оригинал **не** выполняется. Оставьте возвращаемое значение в `r3` (и `f1`). |
| `hook.post(name, fn)` | После возврата функции | `r3` и `f1` содержат возвращаемое значение; его можно изменить. |

Порядок у одной функции такой: все хуки `pre`, затем все хуки `replace` (если есть хоть один, тело пропускается), затем тело, затем все хуки `post`. Хук `post` выполняется и тогда, когда тело заменено. Если установлено несколько замен, выполняются все, в порядке установки, а тело пропускается.

`replace` и `post` требуют `"api": "1.1"`. Если нужно лишь посмотреть аргументы или подправить их, используйте `pre`: он никогда не пропускает собственную работу игры.

## Какие функции можно хукать

`hook.list()` возвращает имена. Сегодня:

| Имя | Адрес | Что это |
|---|---|---|
| `GameWeaponUpdate` | `0x8006C268` | Покадровое обновление оружия игрока. `r3` - **объект** оружия (у игрока он по адресу `player + 0x48`), `r4` - флаг «разрешено». Проверено в игре. |
| `PlayerEventHandler` | `0x800676A0` | Обработчик событий игрока (повреждение, стрельба и подобное). Проверен юнит-тестами, но не подтверждён в живом бою (`unverified`). |

Список растёт с каждым выпуском; актуальная таблица всегда в [справочнике API](../../api/README.md#hookable-functions).

## Примеры

**Посмотреть объект оружия** (id оружия лежит по смещению `0x480`, а магазин - по `0x48C` объекта):

```lua
local last = -1
hook.pre('GameWeaponUpdate', function(regs)
  local id = uc.mem.read_u32(regs.r3 + 0x480)
  if id ~= last then
    last = id
    log.write(string.format('weapon object %08X holds weapon %d', regs.r3, id))
  end
end)
```

**Полностью запретить стрельбу** (замена, которая ничего не делает: оригинальное обновление не выполняется вовсе, поэтому оружие не стреляет и даже не перезаряжается):

```lua
hook.replace('GameWeaponUpdate', function(regs) end)
```

Проверяйте замены внимательно: пропуск всего обновления пропускает и то, что вы могли не хотеть пропускать.

**Отреагировать после функции** (`post` видит результат):

```lua
hook.post('GameWeaponUpdate', function(regs)
  -- regs.r3 - то, что вернула функция
end)
```

## Время и безопасность

- Хуки выполняются в **игровом потоке, внутри функции игры**. Делайте их очень короткими: колбэк относится к тому же классу бюджета, что и шаговые (1 мс на вызов). Не сканируйте память и не стройте таблицы в хуке.
- **Три сбоя** (ошибки или превышения) выключают мод на сеанс; его хуки перестают вызываться сразу.
- Выключение мода или перезагрузка скриптов **снимает хуки** этого скрипта.
- Хук, поменявший регистр на неверное значение, может уронить игру. Проверяйте внимательно и сохраняйте игру перед пробой.
- Функцию, которой нет в списке, **нельзя** хукать или заменять: в ней нет точки хука.
- Из хука можно вызывать функции игры через `uc.guest.call` ([Игровой API](game-api.md#символы-и-вызов-функций-игры)); API разрешает это внутри обработчиков хуков.

## Хуки в нативных модах

DLL использует `hook_pre`, `hook_replace` и `hook_post` таблицы API с колбэком `void callback(UcHookRegs* regs, void* user)`. `regs->r[0]` - это `r3` ... `regs->r[7]` - `r10`; `regs->f[0]` - `f1` ... `regs->f[7]` - `f8`. Функции возвращают 0 или ненулевое значение, если имя нельзя хукать. Подробнее - в [руководстве по нативным DLL](native-dll.md#хуки). DLL, собранная для API 1.1, не загружается в игре, предлагающей только 1.0.

## Устранение неполадок

| Проблема | Вероятная причина и решение |
|---|---|
| Ошибка, называющая `touches_gameplay` | Добавьте `"touches_gameplay": true` в `mod.json`. |
| «not hookable» или неизвестное имя | Функции нет в `hook.list()`. Используйте точное имя. |
| Хук никогда не вызывается | Функция не используется в проверяемой сцене; либо мод выключен после сбоев (смотрите вкладку Mods). |
| Игра падает после хука | Регистру задано неверное значение. Уберите присваивание, сузьте изменение. |
| Эффект пропадает | Хуки снимаются, когда мод выключают или скрипты перезагружают; включайте мод до проверяемой сцены. |
