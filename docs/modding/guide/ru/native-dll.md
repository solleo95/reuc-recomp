# Нативные моды (DLL)

[English](../en/native-dll.md) · **Русский**

Вы здесь: [Руководство по моддингу](README.md) › **Нативные DLL**

Как написать мод на C или C++ в виде DLL для Windows: для работы, для которой скрипты слишком медленны или ограничены, для собственных оверлеев, тяжёлых алгоритмов или вызовов Windows. Это самый мощный вид модов и самый требовательный к аккуратности.

## Когда выбирать DLL

Сначала выбирайте скрипт ([Lua](lua.md), [JavaScript](javascript.md)). Он безопаснее, работает сразу у всех игроков и достаточен почти для всего. Выбирайте DLL, только если нужно:

- **быстродействие**, которого не даёт 1 мс на шаг у скрипта (поиск пути, тяжёлая математика, большие данные);
- **собственное рисование** через Dear ImGui сверх того, что дают виджеты `ui`;
- **вызовы Windows или библиотек** (файлы, сокеты, другие библиотеки).

DLL работает **внутри процесса игры с полными правами учётной записи игрока**. Игроки справедливо к ней осторожны, поэтому публикуйте DLL только с исходным кодом или понятным описанием и будьте готовы, что многие игроки её не включат.

## Что должен сделать игрок

Порт ограничивает DLL двумя шагами; ваши игроки увидят оба:

1. Включить **Allow native mods** на вкладке Mods (по умолчанию выключено; включение показывает предупреждение).
2. **Подтвердить** каждую DLL. Порт запоминает SHA-256 DLL и спрашивает снова, когда файл меняется.

Пока оба шага не выполнены, DLL не работает, и вкладка Mods сообщает об этом. Расскажите игрокам об этих шагах в описании мода.

## Что понадобится

- Компилятор C или C++ для **64-битной Windows** (Visual Studio или clang-cl).
- Заголовок **`uc_mod.h`**: в папке `sdk` рядом с игрой (и `modding/uc_mod.h` в репозитории исходников).
- Если вы рисуете через Dear ImGui: исходники ImGui **точно той версии, что названа в `UC_MOD_IMGUI_VERSION`** в `uc_mod.h` (на момент написания `1.92.9b`).
- `mod.json`, указывающий DLL:

```json
{ "id": "my-native-mod", "name": "My native mod", "version": "1.0", "api": "1.1", "touches_gameplay": true, "native": "native/my_mod.dll" }
```

У мода могут быть и скрипт, и DLL.

## Самая маленькая DLL

```c
#include "uc_mod.h"

UC_MOD_DEFINE_INFO()                       /* экспортирует uc_mod_get_info: версии API и ImGui этой сборки */

static const UcApi* g_api;

static void on_step(const char* payload_json, void* user) {
    (void)payload_json; (void)user;
    /* вызывается около 30 раз за игровую секунду */
}

UC_MOD_EXPORT int uc_mod_init(const UcApi* api) {
    g_api = api;
    api->log("my mod started");
    api->on("on_step", on_step, NULL);
    return 0;                              /* не ноль: мод не загружается */
}

UC_MOD_EXPORT void uc_mod_shutdown(void) {}   /* необязательно, но рекомендуется */
```

Вы экспортируете три вещи:

| Экспорт | Назначение |
|---|---|
| `uc_mod_get_info` (создаётся `UC_MOD_DEFINE_INFO()`) | Сообщает порту, с какой версией API и ImGui собрана DLL. Порт **отклоняет** DLL, у которой его нет, которая собрана под другую мажорную версию API, под более новую минорную, чем у игры, или под другую версию ImGui. |
| `uc_mod_init(api)` | Вызывается один раз при старте мода. Сохраните указатель `api`, зарегистрируйте события и хуки. Верните 0 при успехе. |
| `uc_mod_shutdown()` | Вызывается, когда мод останавливается. Освободите выделенное. |

## Таблица API

`UcApi` - таблица указателей на функции. Вызывайте её **только** из `uc_mod_init` и из ваших колбэков, в том потоке, в котором вас вызывает порт (игровой поток для событий и хуков, поток меню для рисования).

| Член | Применение |
|---|---|
| `log(line)` | Пишет строку в лог мода (`debug\mods.log`). |
| `mem_read`, `mem_write` | Память игры как сырые байты в big-endian. Возвращают 1 при успехе. |
| `get_json`, `set_json`, `call_json` | Весь [игровой API](game-api.md) через JSON-текст. Возвращают 0 при успехе. |
| `settings_get_json`, `settings_set_json` | Объявленные настройки мода. |
| `on(event, callback, user)` | События (`on_step`, `on_load`, ...). Данные - JSON-текст. |
| `hook_pre`, `hook_replace`, `hook_post` | Хуки. |
| `set_ui(draw, user)` | Функция, вызываемая каждый кадр, пока открыто окно настроек. |
| `imgui_context`, `imgui_alloc`, `imgui_free`, `imgui_alloc_user` | Для рисования через ImGui (заполняются прямо перед каждым вызовом вашей функции рисования). |
| `mod_id`, `imgui_version`, `api_major`, `api_minor` | Сведения о вашем моде и сборке. |

Строки, которые порт вам передаёт (`const char** result`), действительны **до вашего следующего вызова API**: копируйте их, если они нужны дольше.

## Игровой API через JSON

`get_json`, `set_json` и `call_json` дают DLL тот же API, что и скриптам. Путь - `область.член`; аргументы - JSON-объект (`slot`, `id`, ...):

```c
const char* out = NULL;

/* чтение: uc.player(1).present */
if (g_api->get_json("player.present", "{\"slot\":1}", &out) == 0) {
    /* out - "true" или "false" */
}

/* запись: uc.player(1).health = 1 */
if (g_api->set_json("player.health", "{\"slot\":1}", "1", &out) != 0) {
    g_api->log(out);                      /* при неудаче out - текст ошибки */
}

/* вызов: uc.game.give_weapon(1, 2) */
g_api->call_json("game.give_weapon", "{\"slot\":1,\"id\":2}", &out);

/* у глобальной области слота нет: uc.game.time */
g_api->get_json("game.time", "{}", &out);
```

Они возвращают 0 при успехе; тогда `out` - значение JSON (для `get` и `call`) или пустая строка (для `set`). При неудаче они возвращают не ноль, а `out` - текст ошибки. Для записи нужен `touches_gameplay`, как и в скриптах.

Для сырой памяти используйте `mem_read` и `mem_write`; они возвращают 1 при успехе и дают байты в порядке **big-endian**, точно как их хранит игра:

```c
uint8_t bytes[4];
if (g_api->mem_read(0x80400000, bytes, 4)) {
    uint32_t value = (uint32_t)bytes[0] << 24 | bytes[1] << 16 | bytes[2] << 8 | bytes[3];
}
```

## События

`api->on(name, callback, user)` регистрирует колбэк `void callback(const char* payload_json, void* user)`. Данные - JSON события: `{}` для `on_step`, `{"slot":1}` для `on_weapon_fired`, `{"id":10,"x":1.5,"y":0.0,"z":4.0}` для `on_enemy_killed`. Имена и данные событий те же, что у скриптов ([Игровой API](game-api.md#события)). Данные можно разобрать любой JSON-библиотекой, а для одного числа поискать в тексте через `strstr`.

## Хуки

```c
static void before_update(UcHookRegs* regs, void* user) {
    (void)user;
    /* regs->r[0] - это r3 ... regs->r[7] - r10; regs->f[0] - f1 ... regs->f[7] - f8 */
    regs->r[1] = 0;                        /* r4 = 0: стрельба в этом шаге не разрешена */
}

/* в uc_mod_init: */
if (api->hook_pre("GameWeaponUpdate", before_update, NULL) != 0) api->log("GameWeaponUpdate cannot be hooked");
```

`hook_replace` и `hook_post` (API 1.1) работают так же; у замены `regs->r[0]` и `regs->f[0]` - возвращаемое значение. Они возвращают 0 или не ноль, если имя нельзя хукать. Что хук может и чего не может, объяснено в [руководстве по хукам](hooks.md).

## Рисование через ImGui

В вашей DLL **собственная копия Dear ImGui** ровно той версии, что в `UC_MOD_IMGUI_VERSION`. В начале **каждого вызова вашей функции рисования** (а не в `uc_mod_init`, потому что контекста там ещё нет) передайте контекст и распределитель игры:

```cpp
static void draw(void*) {
    ImGui::SetCurrentContext(static_cast<ImGuiContext*>(g_api->imgui_context));
    ImGui::SetAllocatorFunctions(g_api->imgui_alloc, g_api->imgui_free, g_api->imgui_alloc_user);

    ImGui::TextWrapped("Hello from a native mod.");
    if (ImGui::Button("Click me")) ++g_clicks;
    ImGui::SliderFloat("a value", &g_value, 0.f, 1.f);
}

/* в uc_mod_init: */
api->set_ui(draw, nullptr);
```

и рисуйте обычные виджеты ImGui. `draw` вызывается каждый кадр, пока открыто окно настроек мода (кнопка с шестерёнкой), внутри окна ImGui, в потоке меню. У неё бюджет 4 мс.

В `uc_mod_init` проверьте, что ваш ImGui совпадает с игровым, и откажитесь загружаться, если нет:

```cpp
if (std::strcmp(IMGUI_VERSION, UC_MOD_IMGUI_VERSION) != 0) return 1;
```

## Сборка

Полный рабочий проект - пример мода `mods-examples\hello_native` (он собирается CMake проекта). Вне репозитория минимальный `CMakeLists.txt` выглядит так:

```cmake
cmake_minimum_required(VERSION 3.20)
project(my_native_mod CXX)
set(CMAKE_CXX_STANDARD 17)

set(IMGUI_DIR "<imgui dir>")                         # версия ImGui, названная в uc_mod.h
set(UC_SDK_DIR "<install dir>/sdk")             # папка с uc_mod.h

add_library(my_mod MODULE src/my_mod.cpp
  ${IMGUI_DIR}/imgui.cpp ${IMGUI_DIR}/imgui_draw.cpp ${IMGUI_DIR}/imgui_tables.cpp ${IMGUI_DIR}/imgui_widgets.cpp)
target_include_directories(my_mod PRIVATE ${IMGUI_DIR} ${UC_SDK_DIR})
set_target_properties(my_mod PROPERTIES PREFIX "" OUTPUT_NAME my_mod)   # my_mod.dll
```

DLL, которая ничего не рисует, не нуждается ни в ImGui, ни в его исходниках. Собирайте для **x64** и копируйте результат в `mods\my-native-mod\native\my_mod.dll`.

## Упаковка нативного мода

Положите DLL в папку `native` мода, укажите её в `mod.json` (`"native": "native/my_mod.dll"`) и упакуйте папку мода в zip ([Тестирование и публикация](testing-and-sharing.md#упаковка-мода)). В описании укажите, что игрокам нужно включить **Allow native mods** и подтвердить DLL.

## Что порт делает для вас

- **Аппаратное исключение** (нарушение доступа и подобное) внутри колбэка перехватывается и считается сбоем вашего мода. Три сбоя выключают мод. DLL остаётся загруженной (порт не может сделать безопасной повреждённую DLL).
- Колбэки **замеряются** после возврата: превышение бюджета (1 мс для шагов, 4 мс для рисования) считается сбоем. Нативный колбэк прервать нельзя.
- Собственные окна Windows с ошибкой «bad image» подавляются; файл, не являющийся DLL, отклоняется с сообщением.
- Когда мод выключают, порт перестаёт вас вызывать, вызывает `uc_mod_shutdown` и возвращает то, что вы задали через API.

## Правила дороги

- Вызывайте API **только** из `uc_mod_init` и своих колбэков, никогда из собственных потоков.
- **Делайте колбэки короткими.** Тяжёлую работу выносите в собственные рабочие потоки и передавайте результаты, но никогда не вызывайте API из них.
- **Копируйте строки**, которые хотите сохранить; строки порта умирают при вашем следующем вызове API.
- **Память:** проверяйте каждый указатель; сбой в вашей DLL уносит всю игру.
- Собирайте под ту же версию API, которую указали в `mod.json`.

## Устранение неполадок

| Проблема | Вероятная причина и решение |
|---|---|
| Вкладка Mods пишет, что нативный код выключен | Включите **Allow native mods** и подтвердите DLL. |
| «refused»: неверная версия API или ImGui | Пересоберите под `uc_mod.h` той игры, на которую ориентируетесь, и с версией ImGui, которую он называет. |
| DLL «не загружается» без сообщения | Это не 64-битная DLL, нет `uc_mod_get_info` (используйте `UC_MOD_DEFINE_INFO()`) или рядом нет нужной зависимой DLL. |
| `uc_mod_init` вернула не ноль, и мод не загружен | Так и задумано: запишите причину через `api->log`, прежде чем вернуться. |
| Интерфейс рисует мусор или падает | Вы не вызвали `SetCurrentContext` и `SetAllocatorFunctions` в начале каждого вызова рисования, либо версия ImGui отличается. |
| Мод сам выключается | Три сбоя: перехваченный сбой в колбэке или превышение бюджета. Смотрите `debug\mods.log`. |
