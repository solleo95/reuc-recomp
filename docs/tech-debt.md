# Tech debt register

Project goal: maximum nativity and performance. Anything that behaves like emulation, or is a stopgap that trades fidelity or speed for progress, is listed here with its native replacement. Newest entries at the bottom of each section. An entry is added in the same step that introduces the stopgap (rule in `docs/superpowers/plans/2026-10-12-runtime-hle.md`, Global Constraints).

Entry format: `TD-nnn` — what it imitates or compromises; why it exists; native replacement; trigger (when to fix); status.

## A. Emulation-like (hardware behaviour imitated instead of native code)

- **TD-010 — EXI bus has no devices.** `EXIImm/EXIDma/EXIImmEx/EXISync/EXISelect/EXILock/...` are replaced at call level (`runtime/hle/exi.cpp`): reads return zeros, `EXIGetID`/`EXIAttach`/`__EXIProbe` report no device. Completion callbacks passed to `EXIImm`/`EXIDma` and the unlock callback of `EXILock` are never called. Consequences: SRAM always comes back invalid (the SDK writes defaults), no RTC, no memory card, no IPL font. Why: a handshake-capable EXI model would be a device emulation. Replace: native services behind the same call boundary (SRAM and settings from a host file, save data on the host file system). Trigger: first game code that needs SRAM values, saves or fonts.
- **TD-011 — DSP boot is skipped.** `__OSInitAudioSystem` (`OSAudioSystem.o`, polls DSP control/mailbox registers for the boot handshake) `DSPInit` (DSP task manager boot, waits for the mailbox handshake) and `__AI_SRC_INIT` (AI sample-rate calibration against the sample counter) are replaced by `Nop`; `DSPAddTask` accepts the task and answers with its init callback in interrupt context (a handshake answer: no microcode runs, so AX never produces a frame); AI/DSP registers stay plain read-back values. Why: the loop waits for hardware that does not exist; a DSP model would be emulation. Replace: native audio engine behind the AX/DSP call boundary (HLE of `AXInit`/DSP task calls, mixing on the host). Trigger: the audio plan; the first AX/DSP mailbox poll in bring-up.
- **TD-012 — Remaining IOS devices absent.** The generic `IOS_*` interface (`runtime/hle/ios.cpp`) still reports missing devices/invalid descriptors. Native NANDInit and verified ISFS calls now use real Windows files under exe_dir()/saves (G10); no IOS device or ioctl interpreter introduced. The startup check reaches the real missing-save/create-data dialog. Remaining gaps: SYSCONF, Bluetooth/Wii Remote, USB, network, and unimplemented NAND/ISFS calls outside the verified subset. Replace: native host services at each required SDK boundary. Trigger: the first call the game depends on; full in-game save/load acceptance still requires native input.
- **TD-013 — Remaining controller services absent.** Native mouse now feeds verified KPADRead/WPADProbe boundaries for player1: raw deltas, pointer validity and real A button edges; other players remain disconnected. KPADInit/KPADEnableMotor still skip Bluetooth/haptic setup. Remaining callbacks, motion actions, configurable button bindings and gamepad support are unimplemented. Replace: native host action/controller services at verified game/SDK boundaries, with actual input and completion. Trigger: a caller requiring another action or controller service; full gameplay/input latency acceptance. Status: partial, G11; no Bluetooth device model introduced.
- **TD-041 — Neutral motion fields in mouse samples.** Mouse-derived KPAD samples expose constant gravity/horizon/distance fields because the host mouse has no IMU or sensor bar. This is an observable compatibility answer and is recorded as emulation-like debt. Replace: verified native game-level pointer/actions that need no invented motion metadata; map required gestures to real host actions. Trigger: first motion-dependent gameplay or calibration call. Status: open; mouse pointer/A edges are real host input and do not run SDK smoothing. Multiplayer/extensions remain absent under TD-013.
- **TD-014 — GX state/copies/materials remain incomplete.** Native GXBegin/SetArray capture descriptor-sized vertex data; GXDrawDone/SetDrawDone/WaitDrawDone use real Vulkan completion. Native Begin/End resource recording owns checked guest bytes and typed host geometry/array/child data without a hardware cursor model. GXCallDisplayList imports these generated resources into owned DrawPackets, reads current indexed arrays and resolves current child revisions; unknown/prebuilt or externally modified lists stop explicitly. Raw state/indexed-XF bytes outside typed boundaries remain discarded/counted. GPU position/projection transforms, persistent native EFB copy-before-clear and owned map0 texture sampling now work. Full TEV/depth/copy semantics and texture routing remain pending (TD-034/036). Headless diagnostics submits no GPU work and leaves graphics waits pending. Why: staged renderer bring-up; no FIFO/list opcode interpreter introduced. Replace: verified call-level state/material/copy boundaries and native prebuilt/inlined resource imports. Trigger: renderer tasks3/5/6/7. Status: open; G7 confirms a recognizable Nintendo wrist-strap startup card; menu/gameplay and scene parity remain pending.
- **TD-017 — VI hardware state is not modelled.** The retrace is a host timer; the SDK retrace handler is replaced (`__VIInit`), so VI status registers (current line, field) read as constants. The retrace count and the pre/post callbacks live in the SDK globals and are driven by the HLE. Replace: expose scan-line/field from the presentation clock when the renderer exists. Trigger: game code that polls `VIGetCurrentLine` or the field.
- **TD-018 — DVD errors and drive state.** Only END, BUSY, CANCELED and FATAL (failed read) are reported; the drive never reports cover-open, retry or wrong-disc states, and `DVDGetDriveStatus` is translated code over untouched state. Replace: native file service with explicit error injection (missing file) mapped to the SDK states. Trigger: the first game path that reacts to a drive error.

## B. Fidelity and correctness gaps in the native code

G11 update to TD-036: verified GXSetBlendMode/SetColorUpdate/SetAlphaUpdate now publish typed native blend state, including resource recording/playback and owned queued draws. Vulkan caches pipelines per blend state; alpha blending, RGB/alpha write masks, subtract and supported logic operations use the GPU. Transparent/half-alpha GPU fixture passes. Real save dialog shows its check/cancel icons and crosshair. Remaining full TEV/texgen/sampler/depth/alpha-compare/EFB pixel-format parity stays open; no unconditional global transparency workaround used.

- **TD-040 — Save permission metadata is provisional.** Native GetAttr checks actual path existence but maps the host owner to RW, with zero UID/GID/attribute; creation validates SDK permissions without persisting them. Why: unblock the verified startup save check while keeping real file results. Replace: persisted native SDK metadata and verified SetAttr support when a real caller requires it. Trigger: save creation/load tests or any permission/attribute-sensitive caller. Status: open; write/read persistence is unit-tested, complete game-format save creation remains unverified. Directory deletion currently accepts only empty directories and archives them; recursive NAND deletion needs verified semantics and preservation tests before use.

- **TD-036 — Partial native texture/material sampling.** Verified GXLoadTexObjPreLoaded owns all eight native binding descriptors and preserves SDK object/cache-region/shadow writes. Published geometry owns decoded map0 texels; recorded bindings retain descriptor values while data is read at playback. Vulkan samples map0/UV0 with nearest/clamp and one mip, multiplied by vertex color. Native GXLoadTlut and C4/C8/C14X2 with IA8/RGB565/RGB5A3 palettes now pass CPU/HLE fixtures and the90-second post-logo run (G8). Full TEV stage routing/ops/registers, channels/texgen/texture matrices and sampler modes/LOD/mips remain pending; GPU multi-mip paths reject explicitly. Replace: verified material state and native pipelines/shaders, with fixtures for every observed mode. Trigger: renderer tasks5/6. Status: open; menu/gameplay/rendering parity unverified. This limited modulation shader remains a compatibility shortcut, not accepted TEV semantics.
- **TD-038 — Native palette region identity.** Palettes own immutable bytes keyed by the SDK region object's address. Distinct region objects aliasing an overlapping physical TLUT range are not unified. No hardware TLUT memory model added. Replace: shared native palette resource identity after a verified aliasing use; preserve call ordering and queued ownership. Trigger: observed custom region callbacks/overlaps or divergent palette fixtures. Status: open; ordinary SDK region reuse and palette replacement covered by tests.

- **TD-031 — SDL startup failure under direct tool-console launch.** Direct PowerShell/native-console startup reproduces access violation in SDL3.dll+0x1A4699 before guest execution, for both release and trace binaries. cmd with file-redirected stderr and Start-Process with redirected output succeed; copied exe from C:/Windows/Temp completes6seconds with validation. Correlation with launch/standard-handle setup is established, underlying SDL/host-window cause is unresolved. Crash handler now reports module/offset. Replace: identify and fix the startup/SDL boundary using a minimal SDL reproduction; no silent fallback or ignored exception. Trigger: launcher work or reproducible normal-user startup failure. Status: open; user's2026-10-12 screenshot confirms an interactive launch reached the white game window.

- **TD-034 — Partial native display-copy semantics.** GXCopyDisp now owns a persistent Vulkan EFB snapshot and optional clear after copy; GXfinish only submits ordered GPU work and its real fence. Current presentation occurs at copy time, before VI-selected XFB scanout; XFB address is validated/retained as identity, no YUV guest-memory copy. Copy crop/scale/filter/gamma, depth attachment/clear, texture copies and recorded display-copy commands remain incomplete. Internal EFB extent stays at the initial render extent across swapchain resize; native blit preserves contents. Why: remove erroneous per-finish clear/present while completing call-level copy integration in stages. Replace: native XFB resources selected by VI, verified copy state and depth/material integration. Trigger: renderer tasks7/8, game framebuffer readback or a recorded copy encountered. Status: open; copy during resource recording fails explicitly, no hardware command interpreter.

- **TD-035 — Synchronization-validation failure with injected rendering.** Enabling VK_LAYER_VALIDATE_SYNC=1 reproduced a real acquire/layout barrier defect; corrected source stage to TRANSFER and that hazard disappears. Remaining PRESENT_AFTER_WRITE refers to vkCmdEndRenderPass, absent from this renderer's dynamic-rendering path. RTSSHooks64.dll remains loaded even with implicit Vulkan layers disabled for the child process. An overlay cause is suspected, not proven by an isolated run. Normal validation GPU fixture passes; full synchronization validation remains failing. Replace: isolate hook-free execution, then fix whichever submission owns the remaining hazard; never suppress validation errors. Trigger: renderer validation/overlay compatibility work before completion of the renderer plan. Status: open; host overlay settings unchanged.

- **TD-030 — Alarm argument ABI.** Closed2026-10-12: OSSetAlarm takes ticks in r5:r6 and handler in r7; periodic start r5:r6, period r7:r8, handler r9. Confirmed DOL80259644/802596B4 and OSSleepTicks802626CC. Original HLE incorrectly used the preceding registers, leaving the resource worker asleep. Corrected native functions and poisoned-r4 regression fixtures;50/50CPUtests pass. Real run now reads script/layout/effect resources and reaches731 GXBegin calls. Related64-bit HLE/vararg implementations must independently verify EABI alignment (TD-022 remains open). No hardware model introduced.

- **TD-001 — Floating-point details differ from the hardware.** SNaN is quieted by host conversions (`lfs`, `stfs`, quantized loads), `fctiw` ignores the FPSCR rounding mode, `fmadds`/`ps_madd` round twice (fma to double, then to float), the 25-bit `frC` rounding of `fmuls`/`ps_mul` is not modelled, `fres`/`frsqrte` are not bit-exact estimates, FPSCR exception bits are not maintained. Why: correct for normal game maths, cheap. Replace: exact Gekko rounding helpers (SSE/AVX) behind the same `op_*` functions. Trigger: a visible or physics difference traced to FP, or the first determinism comparison.
- **TD-002 — Conditional branches with LK=1 set LR only when taken; jump-table `switch` ignores the BO condition of a conditional `bcctr`; conditional `tw`/`twi` are no-ops; `mcrfs` clears whole FPSCR fields.** Not used by `main.dol` today (0 sites). Replace: exact semantics in `emit.cpp` / `ppc_rt.h`. Trigger: another binary, or a mod.
- **TD-003 — Reservation (`lwarx`/`stwcx.`) is one global slot.** Fine while guest threads never run in parallel. Replace: per-thread reservation tied to the final scheduler design. Trigger: any move to real parallel guest threads.
- **TD-016 — Missing production-board metadata.** Closed 2026-10-12: `init_lowmem` writes 0x23 at 0x8000002C. Local DOL `OSGetConsoleType` (802581EC) reads this field and falls back to 10000002 when zero. Production value checked against [WiiBrew's memory-map research](https://www.wiibrew.org/wiki/Memory_map). RED/GREEN lowmem regression; real 20-second run prints `Retail 16` instead of `Emulation platform (10000002)`. No hardware model added. This closes that metadata defect; it did not resolve the missing scene draws.
- **TD-019 — OS object state lives on the host.** Thread state, suspend count, wait queues, mutex owners, message queues and alarms are kept in `Sched`/`os_sync.cpp`/`os_misc.cpp`; only the fields the translated SDK code reads (priority, base priority, state at creation/cancel, stack bounds, current-thread pointer) are mirrored into the guest OSThread. Translated SDK functions that walk guest queues (e.g. `OSCancelAlarms`, `OSGetThreadSpecific`-style helpers, `OSSetThreadSpecific`) see stale data, `OSExitThread` does not release owned mutexes, `OSCreateThread` does not clear `specific[]`. Replace: mirror every transition into the guest structures, or replace the remaining readers. Trigger: a bring-up trace that shows stale guest thread state.

## C. Performance debt in the native code

- **TD-039 — Native async save I/O currently runs under the guest baton.** ISFS async wrappers perform real Windows I/O, then enqueue its actual result/callback for a later scheduler safe point. No fabricated completion or device model, but disk latency blocks guest execution. Replace: owned requests on a joined native worker, validated output publication and callbacks under the baton; cancellation on shutdown. Trigger: measured save latency or larger/streamed save operations. Status: open; callback ordering, interrupt context and real output covered by test_save_hle.

- **TD-037 — Native texture-cache remaining costs.** Content-checked CPU cache now reuses immutable decoded pixels (64MiB/4096-entry limits, LRU); per-slot GPU cache reuses unchanged images and uploads only new versions after the real fence. Measured dialog improved from7–8 to57–60presentations/s, zero steady-state CPU decodes. Remaining costs: whole encoded/palette byte comparisons, per-batch descriptors, and retirement of versions absent from a slot's current packet; alternating copy-only batches can recreate images. Replace: bounded GPU working-set retention and descriptor reuse when profiling justifies it; retain exact invalidation and fence ownership. Status: partially resolved; high-FPS gameplay remains unverified. Evidence: G12-performance-save.md.

- **TD-033 — Position rows repeated in GPU vertex stream.** Native position/projection math executes on GPU;72-byte vertices include48bytes of selected matrix rows plus UV0 so one draw supports multiple position matrices with64-byte projection push constants. Why: verified GPU path using the existing vertex-buffer lifecycle. Replace: shared GPU matrix palette/native mesh cache if upload bandwidth or duplication matters. Trigger: measured high-geometry frame costs after recognizable game image. Status: open; no CPU transform fallback introduced.

- **TD-032 — Native recorded-resource conversion/cache cost.** SDK-generated geometry now reaches owned native DrawPackets without a FIFO/list opcode interpreter. Calls compare the whole retained guest buffer and convert attribute payload again; indexed arrays and child revisions must stay current. Why: correctness before resource-version/cache optimization. Replace: verified resource revisions and reusable native direct-vertex/GPU mesh buffers, with index-source invalidation. Trigger: profiling after recognizable game frame. Limit: resource graph nesting above64 is rejected explicitly; replace recursive traversal if a deeper real asset appears. Status: open; no GPU material/state parity claim.

- **TD-029 — Native vertex decoder rejects NBT3.** Three-index normal/binormal/tangent array offsets need confirmation from actual resources/SDK use. `renderer/gx_vertices.cpp` reports a typed layout error instead of guessing the offsets. Replace: verified NBT3 ingestion at the native array boundary with a fixture using different source indices. Trigger: first observed NBT3 VAT or resource import. Status: open.

- **TD-004 — Guest registers live in the `Ctx` struct, not in host registers/locals.** Every instruction loads and stores through memory. Replace: register caching in locals per function, spilled around calls (spec §5). Trigger: first performance measurement of the running game.
- **TD-005 — Every guest memory access tests the MMIO window.** One predicted compare per access. Replace: constant-propagate known MMIO bases (`lis 0xCC01`) in the translator and use direct access elsewhere. Trigger: profile shows it.
- **TD-006 — Tail calls and secondary-entry stubs rely on clang's sibling-call optimisation (no `musttail`).** A loop across a split entry would grow the host stack in a non-optimised build. Replace: `[[clang::musttail]]` or a dispatch loop. Trigger: stack growth seen in a trace build.
- **TD-007 — Function names from the Dolphin signature database are unverified** (e.g. `J3DGraphLoader` hits are false). Replace: verify by call graph or Ghidra before an HLE replacement relies on a name (`docs/decisions.md`). Trigger: every new HLE mapping.
- **TD-015 — Every backward branch counts toward a safe point.** `ppc::poll` increments `Ctx::poll_count` and calls the scheduler every 2048th time so spin loops see interrupt-driven state. Cost: one add and one predicted test per loop iteration. Replace: poll only in loops that read memory or MMIO (the translator knows), or a flag set by the timer. Trigger: profile shows it.

## D. Scheduling model

- **TD-008 — Guest threads are cooperative: one runs at a time, switches only at blocking calls and safe points.** Not emulation, but it differs from the hardware's preemption and uses one core for all guest code. Replace: keep for fidelity; parallelise only independent subsystems (audio mixing, file streaming, GX command translation) on host threads. Trigger: CPU-bound frame time.
- **TD-009 — No priority inheritance in HLE mutexes.** Replace: implement inheritance in `os_sync.cpp`. Trigger: a priority inversion visible in a bring-up trace.

## E. Known small defects (from the final review of the runtime plan, 2026-10-12)

Not emulation and not blocking M1; fix when the area is touched next.

- **TD-020 — `OSCreateThread` does not clear `specific[]`** (and the join/queue links), so reused heap memory hands stale thread-specific pointers to `OSGetThreadSpecific`. Offsets need a disassembly check first.
- **TD-021 — `OSExitThread`/thread death does not release owned mutexes** (the SDK calls `__OSUnlockAllMutex`); waiters can block forever.
- **TD-022 — Guest printf:** `%ll` should take an aligned register pair in the 32-bit EABI (arguments after it shift); `%*d` is unsupported (`runtime/hle/format_guest.cpp`).
- **TD-023 — `Sched::reschedule` returns for a thread that is still waiting once the main thread has exited** (`sched.cpp`, `if (main_done_) return;`); `block_on` returns unwoken and `~Sched` waits 2 s per host thread. Harmless while the process exits right after main.
- **TD-024 — Guest accesses at the very end of the 1 GiB reservation** (`ea & 0x3FFFFFFF >= 0x3FFFFFF9`) can touch up to 7 bytes past it. Fix: reserve 1 GiB plus a guard region (`guest_mem.cpp`).
- **TD-025 — Analyzer pointer-run rule has no negative test:** a run of switch case-label pointers in a function first found in phase 2 can add its labels as entries (functions get split, translation still works). Add a test and exempt jump-table-shaped runs.
- **TD-026 — Analyzer `lis/addi` rule:** `addi rD,0,imm` (`li`) after `lis r0,hi` is read as `hi:lo`; require `ra != 0`, and clear the remembered `lis` when its register is overwritten (`analyzer.cpp` phase 3).
- **TD-027 — Missing tests:** `tools/hle_cfg.py` (ambiguity error, `@addr` form), `OSSuspendThread`, `OSJamMessage`, blocking send on a full queue, mutex/queue with a suspended waiter, interrupt state inside alarm handlers, async DVD read errors, analyzer negative cases, main-thread identity after `__OSThreadInit`.
- **TD-028 — `docs/spikes/R0-layouts.md` low-memory table** still lists `0x3124/0x3128/0x3130/0x3134` as 0 in the older rows (a note at the end of the file gives the current values).
