## Что такое мод на Lua

Папка в `mods` с файлом `mod.json`, в котором указан файл скрипта:

```json
{ "id": "my-lua-mod", "name": "My Lua mod", "version": "1.0", "api": "1.1", "touches_gameplay": true, "script": "scripts/main.lua" }
```

и сам скрипт, `scripts/main.lua`. Скрипт загружается, когда мод включают. Его задача - **зарегистрировать обработчики** событий и, если нужно, нарисовать окно настроек.

Ставьте `touches_gameplay` в `true`, как только скрипт что-либо **меняет** в игре (записывает значение, включает переключатель, вызывает функцию игры). Скрипту, который только **читает** игру или только рисует окно, этот флаг не нужен.

## Быстрый старт

`mods\hello\mod.json`:

```json
{ "id": "hello", "name": "Hello", "version": "1.0", "api": "1.1", "script": "scripts/main.lua" }
```

`mods\hello\scripts\main.lua`:

```lua
log.write('hello is on')

on('on_step', function()
  if uc.player(1).present and uc.game.time % 10 == 0 then
    log.write('mission time: ' .. uc.game.time)
  end
end)
```

(`uc.game.time` входит в API 1.1, поэтому в `mod.json` указано `"api": "1.1"`.)

Поставьте флажок у мода на вкладке **Mods** и смотрите `debug\mods.log`. Пока вы работаете, **Reload scripts** на вкладке Mods перезапускает скрипты с вашими правками.

## Как выполняется скрипт

1. Файл выполняется **один раз сверху вниз**, когда мод стартует. Всё на верхнем уровне (регистрация обработчиков, создание переменных) происходит тогда.
2. После этого игра вызывает ваши **обработчики**, когда что-то происходит: каждый шаг игры, выстрел игрока и так далее.
3. Когда мод выключают или скрипты перезагружают, выполняется `on_unload`, а всё состояние Lua выбрасывается. Следующий запуск начинается с нуля. Не рассчитывайте, что переменная переживёт перезапуск.

Когда файл выполняется впервые, состояние игры ещё не готово: игра может быть в меню. Настоящую работу делайте в обработчиках и **проверяйте `present`** перед чтением игрока.

## Всё, что доступно скрипту

| Имя | Что это |
|---|---|
| `on(event, fn)` | Зарегистрировать обработчик события. Несколько обработчиков на одно событие допустимы; они выполняются в порядке регистрации. |
| `uc` | Игра: `uc.player(1)`, `uc.weapon(0)`, `uc.enemy(id)`, `uc.enemies`, `uc.game`, `uc.camera`, `uc.input`, `uc.mem`, `uc.symbols`, `uc.guest`. См. [Игровой API](game-api.md). |
| `settings.get(key)`, `settings.set(key, value)` | Собственные объявленные настройки мода ([Настройки и интерфейс](settings-and-ui.md)). |
| `ui.draw(fn)` и `ui.*` | Собственное окно настроек ([Настройки и интерфейс](settings-and-ui.md)). |
| `hook.pre`, `hook.post`, `hook.replace`, `hook.list` | Код внутри функций игры ([Хуки](hooks.md)). |
| `log.write(...)` | Пишет строку в `debug\mods.log` и в консоль. `print` делает то же самое. |
| `require('lib.util')` | Загружает `scripts/lib/util.lua` из папки вашего мода. |

Стандартные библиотеки `string`, `table`, `math` и `utf8` и базовые функции (`pairs`, `ipairs`, `type`, `tostring`, `pcall`, ...) работают как в обычном Lua 5.4. Целые остаются целыми, а дробные - дробными.

## События

Обработчики регистрируются через `on`:

```lua
on('on_weapon_fired', function(e)
  log.write('player ' .. e.slot .. ' fired')
end)
```

| Событие | Когда | Данные |
|---|---|---|
| `on_load` | Мод стартовал | нет |
| `on_unload` | Мод останавливается | нет |
| `on_step` | Около 30 раз за игровую секунду, не во время паузы | нет |
| `on_settings_changed` | Изменилась одна из настроек мода | `{ key }` |
| `on_weapon_fired` | Игрок выстрелил | `{ slot }` |
| `on_reload` | Игрок начал перезарядку | `{ slot }` |
| `on_damage_taken` | Шкала повреждений игрока выросла | `{ slot, amount }` |
| `on_player_died` | Шкала повреждений игрока достигла максимума | `{ slot }` |
| `on_enemy_spawned` | Появился зомби | `{ id, x, y, z, hp }` |
| `on_enemy_killed` | Здоровье зомби упало до 0 или ниже | `{ id, x, y, z }` |
| `on_enemy_headshot` | Зомби отстрелили голову | `{ id, x, y, z }` |

Последние четыре события требуют `"api": "1.1"`. Подробности и примеры по каждому событию - в руководстве [Игровой API](game-api.md#события) и в [справочнике по событиям](../../api/events.md).

`on_step` - сердце большинства модов. Он выполняется с **собственной частотой шагов игры** (около 30 раз за секунду игрового времени), независимо от реальной частоты кадров. Никогда не считайте кадры сами.

## Чтение и изменение игры

Области, которым нужен id или слот, **вызываются как функции** и возвращают дескриптор:

```lua
local p = uc.player(1)          -- слот 1 или 2
p.magazine = 15                 -- запись свойства
local damage = p.damage         -- чтение свойства

local w = uc.weapon(0)          -- запись оружия 0..19
w.damage = w.damage * 2
```

Области без id - обычные таблицы: `uc.camera.position`, `uc.game.time`, `uc.mem.read_u32(addr)`, `uc.enemies.list()`.

Чтение или запись несуществующего члена даёт **ошибку с сообщением, называющим его**; каждый член в [справочнике API](../../api/README.md) помечен `implemented`, `unverified` или `planned`.

Запись требует `touches_gameplay: true`. Без него скрипт получает ошибку, называющую недостающий флаг.

## Рабочие приёмы

**Ждите игрока.** В меню игрока нет:

```lua
on('on_step', function()
  local p = uc.player(1)
  if not p.present then return end
  -- здесь p можно безопасно использовать
end)
```

**Запоминайте исходные значения.** Читайте данные игры в обработчике, а не в начале файла (игра заполняет таблицы позже), и храните копию, чтобы пересчитывать от оригинала:

```lua
local base
on('on_step', function()
  if not base and uc.weapon(0).damage > 0 then
    base = {}
    for id = 0, 19 do base[id] = uc.weapon(id).damage end
  end
end)
```

**Реагируйте на настройки.** Применяйте при старте и снова, когда игрок меняет настройку:

```lua
local function apply() uc.weapon(0).damage = 10 * settings.get('scale') end
apply()
on('on_settings_changed', apply)
```

**Делайте что-то каждые N секунд.** Считайте шаги (30 в секунду):

```lua
local steps = 0
on('on_step', function()
  steps = steps + 1
  if steps % (30 * 10) == 0 then log.write('ten seconds passed') end
end)
```

**Оставляйте всё, как было.** Переключатели и значения оружия, заданные через API, игра возвращает, когда мод останавливается. В `on_unload` нужно убирать только **собственные** изменения (например, память, записанную через `uc.mem`).

## Ошибки

Ошибки игрового API (неверный адрес, отсутствующий игрок, отклонённая запись) - обычные ошибки Lua. Если вы их ожидаете, перехватывайте:

```lua
local ok, err = pcall(function() return uc.camera.position end)
if not ok then log.write('no scene yet: ' .. tostring(err)) end
```

Неперехваченная ошибка в обработчике останавливает этот вызов и считается сбоем мода. После **трёх** сбоев за сеанс мод выключается, пока игрок не снимет и не поставит флажок снова; вкладка Mods показывает последнюю ошибку.

## Разбиение скрипта на файлы

```lua
-- scripts/main.lua
local util = require('lib.util')       -- загружает scripts/lib/util.lua
on('on_step', function() util.heal(1) end)
```

```lua
-- scripts/lib/util.lua
local M = {}
function M.heal(slot)
  local p = uc.player(slot)
  if p.present then p.damage = 0 end
end
return M
```

`require` загружает файлы только из папки вашего мода.

## Примеры

**Немного лечить за каждое убийство** (`touches_gameplay: true`, `api` 1.1):

```lua
on('on_enemy_killed', function()
  local p = uc.player(1)
  if p.present then p.health = math.min(1, p.health + 0.05) end
end)
```

**Быстрый автоматический пистолет** (`touches_gameplay: true`):

```lua
for _, id in ipairs({ 0, 19 }) do
  local w = uc.weapon(id)
  w.fire_mode = 'auto'
  w.fire_rate = 4
end
```

**Счётчик убийств в собственном окне** (только чтение: без `touches_gameplay`, `api` 1.1):

```lua
local kills, heads = 0, 0
on('on_enemy_killed', function() kills = kills + 1 end)
on('on_enemy_headshot', function() heads = heads + 1 end)

ui.draw(function()
  ui.text('Kills: ' .. kills)
  ui.text('Head shots: ' .. heads)
  if ui.button('Reset') then kills, heads = 0, 0 end
end)
```

**Выдать пистолет-пулемёт, когда начинается миссия** (`touches_gameplay: true`, `api` 1.1):

```lua
local given = false
on('on_step', function()
  local p = uc.player(1)
  if not p.present then given = false return end
  if not given then
    given = true
    uc.game.select_weapon(1, uc.game.give_weapon(1, 2, 7))   -- оружие 2, ключ патронов 7
  end
end)
```

Более полные моды лежат в папке [mods-examples](../../../../mods-examples).

## Что недоступно

Скрипт **не может** читать или писать файлы, запускать программы или обращаться к сети. Недоступны: `io`, `os`, `package`, `debug`, `coroutine`, `dofile`, `loadfile`, `load`, `string.dump` и `collectgarbage`, кроме `collectgarbage('count')`. `setmetatable` отклоняет метатаблицу с `__gc`.

## Лимиты

| Лимит | Значение |
|---|---|
| Время на все обработчики `on_step` всех модов вместе | 1 мс на шаг игры |
| Время на один вызов рисования | 4 мс |
| Время на загрузку файла | 2 с |
| Память | 64 МиБ на мод |
| Сбоев до выключения мода | 3 за сеанс |

Скрипт, работающий слишком долго, останавливается ошибкой, которую `pcall` не перехватывает. Делайте обработчики короткими: не сканируйте память и не стройте большие таблицы на каждом шаге.

## Отладка

- `log.write(...)` и файл лога `debug\mods.log` - ваши лучшие друзья. Записывайте в лог значения, в которых сомневаетесь.
- **Reload scripts** на вкладке Mods перезапускает скрипты, не выходя из игры.
- Вкладка Mods показывает последнюю ошибку мода.
- Подробнее - в [Тестирование и публикация](testing-and-sharing.md).

## Частые ошибки

| Ошибка | Решение |
|---|---|
| «Мод ничего не делает» | Флажок стоит? Указан `script`? Указан `touches_gameplay`, когда вы пишете в игру? Посмотрите в лог. |
| Чтение игрока в `on_load` | Игрока там ещё нет. Читайте в `on_step`, проверив `present`. |
| Подсчёт кадров | Используйте `on_step`: он уже в игровом времени. |
| Тяжёлая работа на каждом шаге | Растяните её или сделайте один раз; укладывайтесь в 1 мс. |
| Расчёт на то, что глобальная переменная переживёт перезагрузку | Состояние выбрасывается при каждом перезапуске. |
| `uc.player(1).infinite_ammo = true` без флага | Укажите `touches_gameplay: true` в `mod.json`. |
