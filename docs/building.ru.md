## Как устроена сборка

Порт — это *статическая рекомпиляция*: транслятор читает программу игры для PowerPC (`main.dol`) и пишет для неё исходный код на C++, который компилируется вместе со средой исполнения (память, потоки, Wii SDK, замещённый нативным кодом), рендерерами Vulkan и DirectX, лаунчером и платформой модов.

Из этого следует два вывода:

- **Нужна ваша собственная копия игры**, распакованная с диска: сборка читает `game\DATA\sys\main.dol`. Распакуйте свой образ `RBUE08` (NTSC-U) с помощью Wit, как описано в разделе [Установка](../README.ru.md#2-распакуйте-образ-игры-в-лаунчере-или-с-помощью-wit). Другие регионы не работают.
- Транслированный код записывается в `generated\` (исключено из git). Он получен из кода игры: никогда не коммитьте его, не публикуйте и не прикладывайте к issues или pull request'ам.

## Что понадобится

| Инструмент | Примечание |
|---|---|
| Windows 10 / 11, 64-разрядная | Сборка выполняется на Windows; сборка для Linux (Steam Deck) кросс-компилируется из неё, см. [Сборка для Linux](#сборка-для-linux-steam-deck). Сборки для macOS и Android делаются на Mac: см. [macOS](#сборка-для-macos-apple-silicon) и [Android](#сборка-для-android-ayn-thor) |
| **Visual Studio Build Tools** (или Visual Studio) с рабочей нагрузкой **«Разработка классических приложений на C++»** | Среда MSVC, Windows SDK, компилятор ресурсов |
| **LLVM** с `clang-cl` | Проект собирается `clang-cl` |
| **CMake** 3.25 или новее | |
| **Ninja** | |
| **Python** 3.10 или новее | Скрипты сборки и тестовый стенд (`python` должен быть в `PATH`) |
| **Vulkan SDK** | Должна быть задана `VULKAN_SDK`, в SDK должен быть `slangc` (компилятор шейдеров) |
| Доступ в Интернет при первой конфигурации | CMake скачивает закреплённые SDK NVIDIA Streamline и AMD FidelityFX и некоторые библиотеки (SHA-256 проверяется) |
| Ваша распакованная игра | `...\game\DATA\sys\main.dol` |
| Совместимая видеокарта | Vulkan 1.3, DirectX 11.1 с логическими операциями или DirectX 12 с Shader Model 6.0 и логическими операциями. GPU-тестам нужен выбранный API. См. [поддержку DirectX](directx.md). |

`scripts\env.bat` находит всё перечисленное (вызывает `vcvars64.bat`, ищет `clang-cl`, `cmake`, `ninja` и Vulkan SDK) и сообщает, чего не хватает.

## Пошаговая инструкция

1. Склонируйте репозиторий:

   ```powershell
   git clone https://github.com/solleo95/reuc-recomp.git
   cd reuc-recomp
   ```

2. Создайте `local.env` по шаблону и отредактируйте его:

   ```powershell
   copy local.env.example local.env
   notepad local.env
   ```

   Единственная обязательная строка — `UC_INSTALL_DIR`: папка, где установлена игра. В ней должен лежать `game\DATA\sys\main.dol` (распакованный диск). Готовая сборка копируется в эту папку рядом с `game\`, и в неё можно сразу играть. `local.env` исключён из git и содержит только пути вашего компьютера. Переменная, уже заданная в оболочке, важнее файла. Остальные переменные необязательные, для инструментов разработки; см. комментарии в [`local.env.example`](../local.env.example).

3. Запустите сборку из обычного терминала Windows (PowerShell или `cmd`):

   ```powershell
   .\build.bat
   ```

   Она выполняет шесть шагов: проверяет файлы игры, настраивает и собирает транслятор, транслирует игру (кэшируется по хэшу `main.dol`, транслятора и конфигурации), собирает всё и запускает тесты, раскладывает результат в `dist\` и копирует `dist\` в `UC_INSTALL_DIR`. Первая сборка занимает много времени (трансляция, линковка с ThinLTO); следующие инкрементальные.

4. Запустите `uc_launcher.exe` из папки установки.

## Команды сборки

| Команда | Что делает |
|---|---|
| `build.bat` | Полная сборка, тесты, раскладка в `dist\`, копирование в `UC_INSTALL_DIR` |
| `build.bat --no-install` | То же без копирования (транслятор, сборка, тесты, раскладка в `dist\`) |
| `scripts\dev.bat` | Сборка и тесты только в `build\` (без трансляции и раскладки) |
| `scripts\bringup.bat [аргументы uc.exe]` | Трассировочная сборка в `build-trace\` и короткий запуск (для разработки) |
| `build-release.bat` | Чистый релизный архив, см. [Сборка релизного архива](#сборка-релизного-архива) |

Результаты сборки: `build\` (дерево сборки и журналы: `configure.log`, `translator_build.log`, `translate.log`), `dist\` (разложенная игра), `generated\` (транслированный код). Всё это исключено из git.

**Журналы и отладочные файлы.** Сборка из исходников пишет журналы сессий и отчёты о падениях в `logs\`, а отладочные файлы в `debug\` рядом с `uc.exe` и `uc_launcher.exe`. Установленный релизный клиент (тот, у которого рядом с исполняемыми файлами лежит `release.json` — манифест обновлений) не пишет ничего из этого; исполняемый файл тот же, для `build-release.bat` второй сборки не нужно. Игрок включает журналы флажком «Включить логи» на первой вкладке лаунчера (`"logs": true` в `config.json`): лаунчер передаёт игре `UC_LOGS=1`, а собственный журнал лаунчера пишется со следующего запуска. Для разработчика достаточно переменной окружения `UC_LOGS=1` перед запуском. При жалобе на производительность в папке сессии лежат `frames.csv` (строка на каждый показанный кадр: время кадра, время GPU по проходам, гостевые потоки, чтения диска, текстуры) и `runtime.log`: строки `[hitch]` называют главного виновника каждого кадра, заметно более медленного обычного (`gpu`, `guest-cpu`, `guest-idle`, `present-wait`, `driver-submit`, `render-thread`, `renderer-waits-guest` или `unattributed`), строки `[dvd] open` показывают, какие файлы этапа или ролика игра загружала в это время (каждая строка `[hitch]` и `[hitches]` заканчивается последними открытыми `script=`, `room=` и `movie=`), строки `[pipeline]` показывают компиляцию шейдеров и пайплайнов на всех рендерерах (Vulkan, DirectX 11 и 12), а раз в секунду `[process]`, `[memory]` и `[vram]` сообщают об ОЗУ, загрузке процессора и видеопамяти относительно бюджета.

## Тесты

```powershell
ctest --test-dir build --output-on-failure
```

`build.bat` уже запускает их. Тесты охватывают транслятор, среду исполнения, рендерер, лаунчер, обновлятор, сеть и платформу модов. Некоторым GPU-тестам нужна видеокарта с Vulkan.

**Живые тесты игры.** `uc.exe` управляется тестовым стендом без какого-либо ввода с клавиатуры и мыши (см. [docs/testing/test-server.md](testing/test-server.md)):

```powershell
cd scripts
python -m uctest run train_gameplay --speed 8
```

Стенд копирует ваши сохранения в `build\autotest\<запуск>\saves` и никогда не играет на настоящих. Он всегда использует окно 1280x720; не запускайте тесты в полноэкранном режиме. Изменения производительности сравнивайте детерминированным демо-бенчмарком (`python -m uctest bench`), а не одним замером FPS; правила описаны в [CONTRIBUTING.ru.md](../CONTRIBUTING.ru.md).

## Сборка для Linux (Steam Deck)

Сборка для Linux кросс-компилируется на Windows (clang с sysroot «sniper» из Steam Runtime) и работает на Steam Deck. Ей нужна транслированная игра, как и сборке для Windows (`generated\`), и ещё:

- sysroot: скачайте `com.valvesoftware.SteamRuntime.Sdk-amd64,i386-sniper-sysroot.tar.gz` с <https://repo.steampowered.com/steamrt3/images/latest-public-stable/> и распакуйте командой `python scripts/linux/extract_sysroot.py <archive.tar.gz> <out-dir>` (она работает без прав на символические ссылки);
- LLVM, CMake и Ninja в `PATH` (те же, что для сборки под Windows).

```powershell
pwsh scripts/linux/build.ps1 -Target uc_launcher,uc    # build-linux-znver2\ (под процессор Steam Deck)
python scripts/linux/deck.py package build/deck-release
python scripts/build_release_deck.py --version X.Y.Z --stage build/deck-release   # создаёт UC-Linux-X.Y.Z.zip
```

Как установить и запустить на Deck: [steamdeck-install.md](steamdeck-install.md) (на английском). Правила выпуска (оба архива в каждом релизе) описаны в том же файле.

## Сборка для macOS (Apple Silicon)

Сборка для macOS работает нативно на компьютерах Mac с Apple Silicon и рисует через Vulkan поверх MoltenVK. Она собирается на самом Mac и проверена на M4 с macOS 27. Как и любой сборке, ей нужен **ваш собственный распакованный диск `RBUE08`** в `UC_INSTALL_DIR/game`.

Что понадобится:

- Xcode Command Line Tools (Apple clang): `xcode-select --install`;
- из Homebrew: `brew install cmake ninja sdl3 molten-vk vulkan-loader vulkan-headers` (`ccache` по желанию) и Python 3;
- `slangc`, компилятор шейдеров: распакуйте [релиз Slang](https://github.com/shader-slang/slang/releases) для macOS arm64 и укажите в `local.env` переменную `UC_SLANGC` с путём к его `bin/slangc` (или положите `slangc` в `PATH`, или задайте `VULKAN_SDK`). macOS не запускает скачанную программу, пока с неё не снят флаг карантина: `xattr -dr com.apple.quarantine <распакованная папка>`.
- Чтобы распаковать диск на Mac, используйте [Wit](https://wit.wiimm.de/) для macOS, как в [способе B](../README.ru.md#способ-b-распаковка-вручную-с-помощью-wit). Если его arm64-файл не запускается из-за неверной подписи, подпишите его для этого Mac: `codesign --force -s - wit`.

```bash
cp local.env.example local.env      # укажите UC_INSTALL_DIR (и UC_SLANGC)
scripts/macos/build.sh
```

`scripts/macos/build.sh` проверяет игру и инструменты, собирает транслятор, транслирует `main.dol` (с кэшем, как на Windows), собирает `uc` в `build-macos/` и устанавливает его в `UC_INSTALL_DIR` вместе с **Umbrella Chronicles.app** (`scripts/macos/make_app.sh`): программа, SDL3, шейдеры и ресурсы кладутся рядом с `game/`, как `build.bat` устанавливает игру на Windows. Открывайте приложение двойным щелчком или держите его в Dock. С аргументами `scripts/macos/build.sh <цель>...` собирает только эти цели CMake и ничего не устанавливает.

Игра на Mac: приложение сразу запускает игру (лаунчера пока нет), а настройки находятся во внутриигровом меню, которое открывается клавишей **Tab** (на клавиатурах Mac нет Insert). Геймпады работают через SDL. `config.json`, сохранения и логи остаются в папке установки. Пока нет на macOS: Wii Remote, апскейлеров и трассировки лучей (в MoltenVK нет ни `VK_EXT_dynamic_rendering_unused_attachments`, ни ray query) и 8 из 16 логических операций GX (в Metal их нет: 8 операций, которые для значений 0/1 сводятся к смешиванию, рисуются через коэффициенты смешивания, остальные — простым копированием и один раз называются в логе как `[logic-op]`).

Тесты: POSIX-тесты собираются в `build-macos/tests/linux` (каждая программа `test_*` — один тест). Тестовый стенд тоже работает на Mac: `cd scripts && python3 -m uctest run train_gameplay --exe build-macos/game/uc`.

## Сборка для Android (AYN Thor)

Сборка для Android работает на портативных устройствах arm64 с Android 13 и новее. Она проверена на AYN Thor (Snapdragon 8 Gen 2, Adreno 740). Собирается она на Mac (скрипт использует транслятор из сборки для macOS; транслированный код — один и тот же C++ для всех платформ), поэтому сначала настройте [сборку для macOS](#сборка-для-macos-apple-silicon). Дальше понадобятся:

- SDK из Android Studio с **NDK 27.1** (SDK Manager) и `adb`;
- JDK версии от 17 до 24 для Gradle (собственный JDK 25 из Android Studio слишком новый): `brew install --cask temurin@21`;
- устройство, подключённое по USB, с включённой отладкой по USB.

```bash
scripts/android/build.sh                 # сборка, установка приложения через adb, копирование данных программы
scripts/android/build.sh --copy-saves    # ещё и копирует UC_INSTALL_DIR/saves, если на устройстве сохранений пока нет
scripts/android/build.sh --no-install    # только APK
```

Скрипт собирает библиотеку игры с NDK в `build-android/`, APK — с Gradle (`android/`), устанавливает его и копирует шейдеры, данные программы и ресурсы в `/sdcard/UmbrellaChronicles`, а распакованную игру (`game/`, около 3,8 ГБ) — только в первый раз. Эта папка — папка установки на устройстве, устроенная как на Windows: `game/`, `data/`, `saves/`, `config.json`, `logs/`, `drivers/`.

На устройстве откройте **Umbrella Chronicles** и разрешите **доступ ко всем файлам** (игра, её сохранения и настройки лежат в этой общей папке). На первом экране три кнопки, все работают с геймпада:

- **Play** — играть;
- **Graphics driver** — графический драйвер: системный или свой пакет драйвера Vulkan из `/sdcard/UmbrellaChronicles/drivers` (каждое нажатие показывает следующий);
- **Add a driver (.zip)** — копирует в эту папку выбранный вами пакет.

Пакеты драйверов — в формате AdrenoTools, как у эмуляторов для Android: `.zip` с `meta.json` и библиотекой драйвера. На Adreno 740 выбор очень важен. Собственный драйвер Qualcomm падает в компиляторе шейдеров на специализированных конвейерах игры, поэтому с ним игра рисует всё общими «убершейдерами», и в игровом процессе это медленно (около 8 FPS на Thor в начале миссии в поезде). **Turnip**, открытый драйвер Mesa, справляется со специализированными конвейерами: со [сборкой Turnip от MrPurple](https://github.com/MrPurple666/purple-turnip/releases) та же сцена идёт примерно на 43 FPS. Первый запуск с новым драйвером компилирует его конвейеры (около 35 секунд); следующие запуски занимают доли секунды, потому что кэш конвейеров в `data/` хранится отдельно для каждого драйвера.

Игра: внутриигровое меню — портативное меню Steam Deck, открывается кнопкой **View / Select**. Пока нет на Android: лаунчера (настройки — во внутриигровом меню), Wii Remote, обновлений, вывода HDR; диск нужно распаковать на компьютере.

Логи: вывод игры идёт в logcat с тегом `uc` (`adb logcat -s uc`) и в логи сеанса в `/sdcard/UmbrellaChronicles/logs`. Для диагностики приложение передаёт игре дополнительные параметры `UC_*` как переменные окружения, а `UC_ARGS` — как дополнительные аргументы: `adb shell am start -n org.reuc_recomp.umbrella_chronicles/.LauncherActivity --es UC_ARGS "--render-scale 1"`.

Тесты: тестовый стенд управляет игрой на устройстве через adb: `cd scripts && python3 -m uctest run perf --android --skip-tutorials --measure 15`. `UC_ANDROID_DRIVER=<пакет .zip>` выбирает драйвер для прогона (без неё — системный); папка прогона и её логи потом удаляются с устройства.

## Сборка релизного архива

`build-release.bat` запрашивает версию `X.Y.Z`, запускает `build.bat --no-install`, устанавливает результат в чистую временную папку и создаёт `UC-Windows-X.Y.Z.zip` и `dist-release\` (с `release.json` — манифестом обновления). Подробности и шаги публикации на GitHub: [docs/releasing.md](releasing.md).

## Если что-то не получается

- **`UC_INSTALL_DIR is not set`** — создайте `local.env` (шаг 2) или задайте переменную в оболочке.
- **`main.dol not found`** — нет файла `UC_INSTALL_DIR\game\DATA\sys\main.dol`. Распакуйте туда образ игры с помощью Wit.
- **`clang-cl not found`, `ninja not found`, `VULKAN_SDK is not set`, `slangc.exe not found`** — установите инструмент и откройте новый терминал, чтобы обновились `PATH` и `VULKAN_SDK`.
- **Конфигурация падает при скачивании SDK** — проверьте подключение к Интернету и что прокси не блокирует `github.com`; запустите ещё раз.
- **Сборка или тест падает** — прочитайте журналы в `build\` (`configure.log`, `translator_build.log`, `translate.log`) и вывод `ctest --output-on-failure`. Если считаете, что это ошибка проекта, создайте [issue](https://github.com/solleo95/reuc-recomp/issues) с журналом, но не прикладывайте файлы игры и содержимое `generated\`.
