# Linux: вид «как на Windows» вне Game Mode (лаунчер и меню в игре)

Дата: 2026-11-02. Автор решений: владелец (его слова отмечены «владелец»); остальное решения исполнителя, помечены «моё решение».

## Зачем

Сейчас на Linux всегда запускаются Deck-лаунчер (`launcher/deck/main_deck.cpp`) и Deck-меню в игре (`game/deck_menu.*`, кнопка View). Они сделаны под экран и геймпад Steam Deck в Game Mode. Человеку на обычном Linux-десктопе (и на Deck в Desktop Mode) нужен тот же вид, что на Windows: тот же лаунчер и то же меню на Insert, со всеми настройками, которые на Linux поддерживаются. Deck-вид остаётся только там, где игра запущена в Game Mode (Steam Deck и устройства с SteamOS, у которых есть Game Mode).

Проверять владелец будет только на Steam Deck в Desktop Mode. Обычного Linux-ПК у него нет (владелец).

## Что должно получиться (владелец)

1. Пользователь запускает `uc_launcher` или `uc-launcher.sh` вне Game Mode и видит такой же лаунчер, как на Windows, без Windows-специфичных частей (DX11/DX12 и подобное).
2. Пользователь запускает `uc` или `uc.sh` напрямую вне Game Mode и видит в игре такое же меню на Insert, как на Windows.
3. В Game Mode всё остаётся как сейчас: Deck-лаунчер и Deck-меню.
4. Есть явный переключатель вида, чтобы форсировать любой вид (для тестов). Определение Game Mode должно быть просто надёжным.
5. У Linux-лаунчера своя логика обновлений (уже есть: архив `UC-Linux-<версия>.zip`, `update_posix.cpp`).

## Решения

**Определение вида** (моё решение, по реальному окружению Deck и по тому, как это уже делает код): Game Mode, если процесс работает внутри сессии gamescope, то есть задана `GAMESCOPE_WAYLAND_DISPLAY` (в Game Mode она есть, `steam-env.txt` на Deck; так же решают `main_deck.cpp` и слой HDR в `uc_main.cpp`). `SteamGameId` в условие не входит: если ярлык или обёртка его потеряет, Game Mode не должен молча стать Desktop. В Desktop Mode gamescope нет. Тот, кто запускает игру во вложенном gamescope на десктопе, форсирует `--ui desktop`. Существующие ручные проверки в `main_deck.cpp`, `compile_screen_posix.cpp`, `uc_main.cpp` (HDR) и `steam_overlay.cpp` не трогаем (меньше риск для Game Mode); на общую функцию переходит только выбор вида. Приоритет: аргумент `--ui desktop|deck`, затем переменная `UC_UI=desktop|deck`, затем автоопределение. Неизвестное значение переключателя: сообщение об ошибке и завершение, без молчаливого выбора.

**Один бинарник на каждую программу** (владелец): `uc_launcher` и `uc` содержат оба вида и выбирают при запуске. Лаунчер, запуская игру, передаёт ей выбранный вид (моё решение), иначе принудительный вид в лаунчере разошёлся бы с игрой. Скрипты `uc-launcher.sh` и `uc.sh` ничего не выбирают сами, а передают аргументы.

**Что скрывать из Windows-вида на Linux** (моё решение): скрывать, а не показывать отключённым: DX11/DX12, DLSS/Streamline и всё, что опирается на Windows. Источник правды: таблица `launcher/settings_registry.cpp` и отчёт о возможностях, который игра отдаёт лаунчеру (`uc --features`). Нативные DLL-моды: на Linux не поддерживаются, скрыть (проверить, как они устроены в Windows-меню).

**Сетевая игра** (владелец): вкладка сетевой игры в Linux-лаунчере пока не нужна. Её код (`uc_nat`, UPnP, STUN, enet, `network_session`) на Linux не собирается и остаётся Windows-only; вкладку на Linux скрыть. Сама сетевая игра внутри `uc` не затрагивается.

**Тесты на Deck** (моё решение): сценарии `uctest`, которым нужно именно Deck-меню, получают явный `--ui deck`. Остальные запуски в Desktop Mode покажут Windows-вид.

## Решения исполнителя по итогам независимой проверки описания (проверьте при чтении)

- **Состав настроек в десктопном виде:** ровно то, что показывает Windows-лаунчер и Windows-меню, минус Windows-специфичное. Deck-only элементы (кнопка гироскопа, «Recenter aim», выбор пути игры в стиле Deck, «Quit game») в десктопном виде не появляются, потому что вы просили «точно такой же, как на Windows». Видимость FSR, генерации кадров, трассировки и выбора рендера берётся из отчёта `uc --features` (на Deck `vendor_upscalers=false`), как и на Windows; скрываем явно только DX11/DX12, DLSS/Streamline, CPU-калибровку, DLSS-панель, сетевую вкладку. Если таблица `settings_registry` не даёт признака «только Windows», добавляется поверхность (surface) или условие в самом виджете; тест проверяет список скрытых настроек.
- **Запуск игры из десктопного лаунчера:** как на Windows (запуск процесса, лаунчер остаётся или закрывается так же, как на Windows), а не `exec`, как у Deck-лаунчера. Это относится и к принудительному `--ui desktop` внутри Game Mode.
- **Общий файл настроек:** один `config.json` в папке игры для обоих видов (игра одна). Значения, которые Game Mode задаёт сам при запуске (HDR 400/300 нит и т. п.), применяются в рантайме и не читаются из файла; нужно проверить в коде, что десктопный вид их не перезаписывает, и если перезапишет, защитить эти поля.
- **Проверка кадра лаунчера:** через встроенный в лаунчер режим smoke/снимка (`SDL_RenderReadPixels`, BMP), как уже сделано для Deck-лаунчера (`tools/compile_screen_snapshot`); рабочий стол не снимаем. Эталон Windows-лаунчера снимается тем же режимом на ПК.
- **Основа работ:** рабочее дерево с текущими незакоммиченными изменениями (переименованные `uc-launcher.sh` и `uc.sh` и т. д.); коммиты делаем только по вашей просьбе.
- **Проверка Game Mode (регрессия):** запуск через ярлык Steam в Game Mode (`UC_DECK_GAMEMODE=1`, как у harness) обязан показать Deck-вид; это единственный способ убедиться, что определение не сломало Game Mode.

## Части работы

1. **Меню в игре.** `game/uc_main.cpp`: Windows-меню (`settings_menu`) уже создаётся на Linux. Deck-меню (`deck_menu`) сейчас создаётся безусловно при `#ifndef _WIN32`: заменить на условие «вид = deck». Проверить, что Insert и геймпад открывают Windows-меню на Linux, и что окно меню, фокус и ввод работают под Wayland на Deck.
2. **Выбор вида.** Одна маленькая общая функция (в `common/` или `launcher/`): читает `--ui`, `UC_UI`, окружение; используется лаунчером и игрой. Тест на таблице окружений (Game Mode, Desktop Mode на Deck, обычный Linux, принудительные значения, неверное значение).
3. **Лаунчер.** Windows-лаунчер (`launcher/main.cpp`, 113 КБ) собрать на Linux как «десктопный вид». Привязки к Windows, которые нужно закрыть Linux-аналогами или убрать: `windows.h`, `shellapi`, `dwmapi` (тёмный заголовок окна), `d3d11/dxgi` (название GPU), `GetModuleFileNameW`, `graphite.cpp` (WIC и системный диалог выбора файла; для Linux есть `graphite_posix.cpp` и ImGui-обозреватель файлов Deck-лаунчера), `ui_fonts.cpp` (Windows-папка шрифтов; ветка для Linux уже есть), `cpu_calibration` (Windows-only, скрыть), DLSS-панель (скрыть), `uc_launch` (на Linux есть `launch_posix.cpp` и `image_unpack_posix.cpp`, `update_posix.cpp`). Deck-лаунчер (`main_deck.cpp`) остаётся без изменений поведения, его `main` становится функцией «запустить Deck-вид».
4. **Точка входа лаунчера.** Новый небольшой `main` на Linux: выбрать вид, вызвать функцию нужного вида. В CMake на Linux в `uc_launcher` линкуются оба вида.
5. **Передача вида игре.** `launch`/`exec_game`: добавить `--ui <вид>` в аргументы запуска игры.
6. **Документация.** `docs/steamdeck-install.md`: как запустить вне Game Mode, переключатель `--ui`.

## Что считать готовым

- На Deck в Desktop Mode `uc_launcher` показывает Windows-лаунчер: вкладки, настройки графики и управления, моды, выбор игры, язык; без DX11/DX12/DLSS. Кадр сравнён со скриншотом Windows-лаунчера (что совпадает, что скрыто).
- На Deck в Desktop Mode `uc` по Insert показывает Windows-меню; настройки применяются, как на Windows.
- С `--ui deck` в Desktop Mode и в Game Mode без переключателя показывается Deck-вид, как сейчас (кадры совпадают с нынешними).
- Все существующие тесты проходят; новые тесты: выбор вида, список скрытых настроек.
- Кадры и видео проверки: только игровые снимки, не рабочий стол пользователя.

## Не цели

- Вкладка сетевой игры на Linux.
- Поддержка других оболочек или видеокарт, кроме проверки на Deck.
- Переименование `Platform::steamdeck` в апдейтере, новые функции лаунчера, смена архитектуры настроек.
- Нативные DLL-моды на Linux.

## Что оставлено исполнителю

Внутреннее устройство функции выбора вида и её место в дереве; порядок работ (меню в игре проще и идёт первым); как именно закрыть каждую Windows-привязку (аналог на Linux или скрыть), если это не меняет вид лаунчера; имена файлов и тестов.

## Риски

- `main.cpp` лаунчера большой и мог неявно зависеть от Windows; тихие различия поведения (шрифты, масштаб, фокус окна под Wayland).
- Окно Windows-лаунчера 1200×820 на экране Deck 1280×800: проверить, что оно помещается.
- Принудительный `--ui deck` на ПК без геймпада: Deck-вид должен хотя бы запускаться.
