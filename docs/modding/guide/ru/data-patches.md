## Что такое патч данных

Патч данных - это JSON-файл в папке `data` мода. Он сопоставляет **названия значений игры** с **новыми значениями**. Когда мод стартует, порт записывает каждое значение в игру точно так же, как это сделало бы присваивание в скрипте. Когда мод выключают, собственные значения игры возвращаются.

Используйте патч данных, когда нужно только **один раз задать** числа. Если значение должно от чего-то зависеть (здоровье игрока, смерть врага, настройка), пишите скрипт на [Lua](lua.md) или [JavaScript](javascript.md).

## Быстрый старт

Пистолет с магазином на 30 патронов и быстрой перезарядкой:

`mods\faster-handgun\mod.json`

```json
{
  "id": "faster-handgun",
  "name": "Faster handgun",
  "version": "1.0",
  "api": "1.0",
  "touches_gameplay": true
}
```

`mods\faster-handgun\data\handgun.json`

```json
{
  "weapon.0.capacity": 30,
  "weapon.0.reload_time": 0.3,
  "weapon.19.capacity": 30,
  "weapon.19.reload_time": 0.3
}
```

Записи оружия 0 и 19 - обе варианты пистолета, поэтому меняются обе. Запустите игру, поставьте флажок у мода на вкладке **Mods**: пистолет перезаряжается за треть секунды и вмещает 30 патронов (магазин пополняется при следующей перезарядке).

Мод может состоять только из файлов данных; поле `script` ему не нужно. Мод, меняющий ход игры, всё равно указывает `"touches_gameplay": true`.

## Формат файла

- Файл данных - **один JSON-объект**: `{ "ключ": значение, "ключ": значение }`.
- В папку `data` можно класть сколько угодно файлов; читается каждый `.json`.
- Файлы больше 1 МиБ, файлы, не являющиеся корректным JSON, и файлы, корнем которых не служит объект, пропускаются с сообщением в логе.

## Какие ключи можно использовать

Ключ имеет вид `<область>.<id>.<член>` или `<область>.<член>`, если у области нет id. Это то же имя, которое вы использовали бы в скрипте, только с точками вместо скобок: `weapon.0.damage` - это `uc.weapon(0).damage`.

Записываемые значения, которые имеет смысл задавать патчем данных:

| Ключ | Значение | Смысл |
|---|---|---|
| `weapon.<id>.damage` | число от 0 до 10000 | Урон за попадание |
| `weapon.<id>.fire_rate` | число от 0,05 до 60 | Выстрелов в секунду |
| `weapon.<id>.capacity` | целое от 0 до 999 | Размер магазина |
| `weapon.<id>.reload_time` | число от 0 до 1000 | Время перезарядки в секундах |
| `weapon.<id>.fire_mode` | `"semi"`, `"auto"`, `"burst"` | Одиночные выстрелы, зажатый курок повторяет, очередь |
| `player.<slot>.invulnerable` | `true` / `false` | Игрок никогда не получает урон |
| `player.<slot>.infinite_ammo` | `true` / `false` | Магазин пополняется каждый шаг |
| `game.stars` | целое от 0 до 9999 | Деньги на улучшения |

`<id>` - номер записи оружия от 0 до 19, `<slot>` - 1 или 2.

Записываемы и другие члены [игрового API](game-api.md) (`player.<slot>.magazine`, `player.<slot>.grenades`, `game.time` и т. д.), но патч данных применяется **один раз при старте мода**. Значения игрока, которого ещё нет, в этот момент задать нельзя. Для всего, что требует идущей миссии, используйте скрипт.

Полный список членов и их пределов - в [справочнике игрового API](../../api/README.md).

## Порядок и конфликты

- Файлы в `data` применяются **по порядку имён**; ключи применяются в порядке их появления в файле.
- Моды применяются в **порядке загрузки** (сначала верх списка вкладки Mods).
- Если два патча задают одно значение, **побеждает последний**.
- Патчи применяются один раз при старте мода, **после `on_load` скрипта**, если скрипт есть.

## Что пропускается

Не работающий ключ пропускается и записывается в лог (имя файла и причина), а остальная часть файла применяется:

- ключа нет, либо член не реализован;
- член только для чтения (например, `camera.view`);
- id не является целым числом, либо в ключе не хватает или лишняя часть;
- у значения неверный тип, либо оно вне допустимого диапазона.

После пробы патча прочитайте `debug\mods.log`: каждый пропущенный ключ перечислен там.

## Когда патча недостаточно

- Значение должно зависеть от **настройки**, которую выбирает игрок: используйте скрипт с [объявленными настройками](settings-and-ui.md) (именно так сделан [пример множителя урона](../../recipes.md)).
- Значение должно **меняться во время миссии** (пополнение, лечение, таймер): используйте скрипт и `on_step`.
- Нужно реагировать на **события** (враг умер, игрок выстрелил): [Lua](lua.md) и [события](game-api.md#события).

## Устранение неполадок

| Проблема | Вероятная причина и решение |
|---|---|
| Ничего не меняется | В моде нет `touches_gameplay: true` (лог об этом сообщит), файл лежит не в `data\` либо JSON некорректен. Загляните в `debug\mods.log`. |
| «unknown key» в логе | Опечатка в ключе; сверьтесь с таблицей выше или справочником API. |
| Значение вне диапазона | См. пределы в таблице; порт отклоняет значение, а не обрезает его. |
| Значение оружия «возвращается» | Этого не происходит: значения сохраняются. Возможно, то же значение задаёт другой мод ниже вашего; поменяйте порядок. |
| Магазин не меняется | Новое `capacity` вступает в силу при следующей перезарядке. |
