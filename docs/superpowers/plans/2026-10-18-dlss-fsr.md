# DLSS 4.5 and FSR 3.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** DLSS 4.5 SR + DLSS-G (Streamline) and FSR 3.1 + FSR 3.1 FG (FidelityFX SDK 1.1.4) in the Vulkan renderer, with five quality modes, RCAS sharpening and launcher controls.

**Architecture:** With an upscaler on, each guest frame renders its 3D scene into internal-resolution targets (color, depth, motion) with a projection jitter; at a detected scene/HUD boundary an `Upscaler` reconstructs into the existing output-resolution EFB (`efb_`), RCAS runs, and the rest of the frame (post chain, HUD, prompts, reticle) draws at output resolution as today. Motion vectors come from a CPU `MotionTracker` that pairs draws across frames and hands the shader the previous palette and projection. Frame generation hooks presentation: Streamline intercepts present for DLSS-G, the FFX Vulkan frame interpolation swapchain replaces the swapchain functions for FSR FG. All settings are fixed at process start (launcher → `config.json` → `uc.exe`).

**Tech Stack:** C++20, Vulkan 1.3 (dynamic rendering), Slang shaders (`slangc`), CMake FetchContent, NVIDIA Streamline 2.14.16, AMD FidelityFX SDK 1.1.4 (FFX API, `amd_fidelityfx_vk.dll`), ImGui launcher, `tests/check.h` test executables + ctest, `scripts/uctest` harness.

**Spec:** `docs/superpowers/specs/2026-10-18-dlss-fsr-design.md`

## Global Constraints

- Streamline SDK 2.14.16: `https://github.com/NVIDIA-RTX/Streamline/releases/download/v2.14.16/streamline-sdk-v2.14.16.zip` (276016170 bytes). Production (signed) binaries in `dist`.
- FidelityFX SDK v1.1.4: `https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/releases/download/v1.1.4/FidelityFX-SDK-v1.1.4.zip` (470858939 bytes). No FSR SDK 2.x, no DirectX 12.
- Modes and ratios: native 1.0, quality 1.5, balanced 1.724, performance 2.0, ultra_performance 3.0. DLSS presets: native/quality/balanced → `DLSSPreset::eK`, performance → `eM`, ultra_performance → `eL` (Streamline `ePresetK=11`, `ePresetM=13`, `ePresetL=12`). DLSS modes: `eDLAA`, `eMaxQuality`, `eBalanced`, `eMaxPerformance`, `eUltraPerformance`. FSR modes: NativeAA, Quality, Balanced, Performance, UltraPerformance.
- Output resolution = the render-scale extent (`efb_extent_` today). Internal = output / ratio, rounded with `std::llround`, at least the SDK minimum.
- Sharpness 0.01..1.00 in 0.01 steps plus an on/off flag. RCAS constant for both upscalers: `exp2(-(2 - 2*sharpness))` (FidelityFX remap `-2*s+2` stops).
- Frame generation: DLSS ↔ DLSS-G, FSR ↔ FSR FG; multiplier from `numFramesToGenerateMax + 1` (DLSS-G) or 2 (FSR FG). The frame limit is the rendered rate; presented = limit × multiplier. Reflex on whenever DLSS-G is on. No VSync with FG. Present mode stays mailbox/immediate except the FSR-FG FIFO fallback in Task 12.
- Deterministic runs (`--deterministic`, `--det-out`, demo, bench) force frame generation off; upscaling is allowed.
- Harness only for live runs (`AGENTS.md`): `cd scripts && python -m uctest run <scenario>`; never real saves; one or two live runs per question; performance only with `python -m uctest bench <A> <B> --demo fight2`.
- Source edits only with Edit/Write (no heredoc/sed patches). Commits only when the owner asked for them.
- Build: `build.bat --no-install`; tests: `ctest --test-dir build --output-on-failure`.

## Review Focus

1. Window resize, borderless/exclusive switch or minimize while an upscaler is on: the upscaler and internal targets are recreated at the new output size, no crash, no stretched frame. Test in Task 6.
2. Tiny outputs (render scale 0.5 → 640x360 output with ultra_performance gives 213x120): internal extent is clamped to the SDK minimum, never 0 or below it. Test in Task 2 and Task 9/11.
3. `upscaler: dlss` on a machine without NVIDIA RTX, with a missing Streamline/DLSS DLL, or FG requested where unsupported: the game starts with upscaling (or FG) off and one log line naming the reason. Test in Task 8.
4. Movies, `black_output` frames and camera cuts with an upscaler and FG on: upscaler reset that frame, FG skips generation, no smeared frame. Test in Task 10/12 live check.
5. Determinism: `--det-out` hashes with an upscaler on equal those with it off (the guest never sees renderer state). Test in Task 6.

### Task 4: Motion tracker

**Files:**
- Create: `renderer/motion_tracker.h`, `renderer/motion_tracker.cpp` (in `uc_gx`)
- Test: `tests/test_motion_tracker.cpp`

**Interfaces:**
- Produces (namespace `gx`):
  `struct DrawKey { uint32_t callsite; const void* mesh; uint32_t vertices; uint32_t occurrence; auto operator<=>(const DrawKey&) const=default; };` (`mesh` null for non-mesh draws; `occurrence` counts equal (callsite, mesh, vertices) within the frame)
  `struct PreviousDraw { PaletteBlock palette; Projection projection; };`
  `class MotionTracker { public: void begin_frame(); DrawKey key(const DrawPacket&); const PreviousDraw* previous(const DrawKey&) const; void record(const DrawKey&, const Transforms&); bool camera_cut() const; Projection clip_to_prev_clip() const; void end_frame(); };`
  `previous` returns the entry recorded for the same key in the last frame, `nullptr` when unpaired. Unpaired draws get camera-only motion: the shader applies the previous frame's `clip_to_prev_clip()` to their current clip position (camera motion is assumed steady across one frame; the current frame's estimate is not known until all its draws arrived). `end_frame` swaps current into previous and computes `camera_cut` and `clip_to_prev_clip` for the frame just finished.
  `camera_cut()`: median over paired mesh draws of the screen-space displacement of the object origin (current vs previous modelview × projection, in NDC) above `kCameraCutNdc = 0.5f`, or projection change above `kProjectionCutRelative = 0.2f` relative on `[0][0]`/`[1][1]`. Named constants, tuned in Task 14.
  `clip_to_prev_clip()`: `P_prev * MV_prev * inverse(P * MV)` from the paired z-writing mesh draw with the most vertices (the level geometry), identity when none.

### Task 5: Motion vector shader variant and pipelines

**Files:**
- Modify: `renderer/shaders/smoke.slang`, `renderer/CMakeLists.txt` (compile `-DMOTION` variants `smoke.motion.vert.spv`, `smoke.motion.frag.spv`, `smoke.motion.uber.spv`; install them in `game/CMakeLists.txt` next to the others), `renderer/vulkan_renderer.cpp` (`DrawPush`, `make_pipeline`, device creation)
- Test: `tests/test_pipeline_keys.cpp` (attachment write masks), `tests/renderer_smoke.cpp` (a motion case)

**Interfaces:**
- `DrawPush` grows to `{ Projection projection; uint32_t palette, current_row, indexed, alpha_pass, bank; uint32_t motion; float jitter[2]; float viewport[4]; }` (≤128 bytes; `motion` = index into a new storage buffer binding 5 of `MotionBlock { float4 prev_rows[4]; uint prev_palette; uint kind; }` in the texture descriptor set layout; `kind` 1 = paired (previous palette + `prev_rows` as projection), 2 = camera-only (`prev_rows` = `clip_to_prev_clip`, applied to the current clip position); `motion=0xFFFFFFFF` for draws after the cut).
- Motion variant: vertex shader adds `jitter` (internal pixels → NDC, `clip.xy += jitter_ndc * clip.w`) and outputs unjittered current and previous clip positions; the fragment shader writes `SV_Target1` = RGBA16F: `rg` = (previous pixel − current pixel) / target size (UV units, current→previous), `b` = reactive (Task 14), `a` unused. Previous pixel uses the same per-draw `viewport`.
- Pipelines built with 2 color attachments (formats of `efb_` and `R16G16B16A16_SFLOAT`) only when `motion_outputs_` is set (upscaler on). Attachment 1 write mask: `RG` when the draw's depth state has z-update, else `0`; blending off for attachment 1. Passes without a motion target bind `VK_NULL_HANDLE` for attachment 1, which needs `VK_EXT_dynamic_rendering_unused_attachments` (enabled at device creation when the upscaler is on; missing → upscaler off with a log line).
- Produces: `void VulkanRenderer::configure_upscaling(UpscalerKind, UpscaleMode, bool sharpening, double sharpness, bool frame_generation, uint32_t multiplier)` called before `initialize` (sets `motion_outputs_` and the rest; settings never change at runtime).

```cpp
struct UpscaleImage { VkImage image; VkImageView view; VkFormat format; VkExtent2D extent; VkImageLayout layout; };
struct UpscaleInputs {
    VkCommandBuffer command;
    UpscaleImage color, depth, motion, output;   // color/depth/motion at internal size, output = efb_
    std::array<float,2> jitter;                  // internal pixels, as applied
    std::array<float,2> motion_scale;            // multiplies stored UV motion to the SDK's convention
    bool reset; float sharpness;                 // sharpness < 0: off
    float frame_ms; uint64_t frame;
    gx::Projection projection, clip_to_prev_clip;
};
class Upscaler {
public:
    virtual ~Upscaler()=default;
    virtual void resize(VkExtent2D internal, VkExtent2D output)=0;
    virtual void evaluate(const UpscaleInputs&)=0;   // records into inputs.command; output left in COLOR_ATTACHMENT_OPTIMAL
    virtual bool sharpens() const=0;                 // true: the upscaler applied RCAS itself (FSR)
    virtual RenderExtent minimum_internal(VkExtent2D output) const=0;
};
std::unique_ptr<Upscaler> make_blit_upscaler(VkDevice);   // test-only: linear blit internal → output
```

- Renderer: `scene_color_`, `scene_depth_`, `scene_motion_` at `internal_extent(efb_extent_, mode, upscaler->minimum_internal(...))`, rebuilt in `rebuild()` with the EFB (Review Focus 1). `render()` draws into an "active target" (`scene_*` while the frame is in scene phase, else `efb_`/`depth_`); every place that maps 640x480 coordinates (`efb_viewport`, scissor, copy and clear rectangles) uses the active target's extent. `SceneBoundary::on_packet` (Task 3) decides the cut; at the cut: end rendering, `MotionTracker`-driven `evaluate`, RCAS (Task 7) unless `sharpens()`, blit `scene_depth_` → `depth_` with `VK_FILTER_NEAREST`, resume rendering into `efb_`. - `UC_MOTION_DEBUG=1`: the present shows `scene_motion_` as color (|rg| scaled ×50) instead of the frame.
