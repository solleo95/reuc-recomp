# GX → Vulkan: первая картинка игры — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Режим исполнения: Native, выбран пользователем. Шаги отмечать `- [ ]`. Финальное ревью изменений: свежий агент `gpt-6-astra`.

**Goal:** вывести узнаваемый кадр Umbrella Chronicles через собственный Vulkan-рендерер, подтвердить реальные GX draw-вызовы, корректное завершение GPU-работы и масштабирование внутреннего разрешения до 3840×2160.

**Architecture:** проверенные GX-функции заменяются нативными HLE-вызовами. Они формируют снимки состояния и владеющие данными draw-пакеты; Vulkan исполняет их на основном потоке приложения. Короткий форматный декодер читает атрибуты вершин между GXBegin и концом примитива; общий эмулятор GX FIFO в этот план не входит.

**Tech Stack:** C++20, clang-cl, CMake/Ninja, Vulkan 1.3, Slang → SPIR-V; SDL3 для окна и событий. Установленный Vulkan SDK: 1.4.363.0. SDL — одна фиксированная исходная версия `release-3.2.0` (минимум API 3.2.0), хеш архива фиксируется до подключения; SDK Slang уже установлен.

**Spec:** `docs/superpowers/specs/2026-10-12-uc-recomp-design.md`, §7; `docs/decisions.md`; `docs/tech-debt.md`, TD-014/017/019/023/024. Основание: коммит `451b32fcae18e119d72f6c3ffba5f17465182839`.

## Ограничения и границы этапа

- Максимум нативности и производительности; весь игровой код компилируется заранее в x64. Интерпретатор/JIT PowerPC исключены.
- Существующие модели регистров остаются простыми. Новые аппаратные рукопожатия заменять на границе SDK; каждую временную потерю поведения записывать в `docs/tech-debt.md` вместе с нативной заменой.
- Статические шейдеры собираются при сборке проекта. Интерпретация TEV в универсальном GPU-шейдере — временный путь с отдельной записью техдолга; специализированные шейдеры следуют после проверки изображения и профиля.
- Код Dolphin/aurora/Wiicompiled не копировать. Их документация и форматы — проверяемые источники; адреса и ABI GX подтверждаются по пользовательскому DOL.
- Вывод: `<project>/dist`; установка: `S:\Games\Umbrella Chronicles`. Сохранить ручной `build.bat`, headless runtime-проверку и CLI `--game`.
- Удаление файлов — только по запросу пользователя. Никаких очисток через `rmdir /s`, `/MIR` или скрытого удаления восстановленных частей планов. Для устаревших сгенерированных шардов использовать список файлов текущего поколения при сборке.
- Коммиты и push — только по отдельному запросу. Ghidra пока отложена; обращаться к пользователю при доказанном пробеле идентификации.
- SDL и Vulkan находятся на основном потоке. Только этот поток владеет Vulkan-очередью, ресурсами и swapchain. Игровой runtime передаёт пакеты через ограниченную очередь; данные гостевой памяти копируются до публикации.
- Счётчики ретрейсов, draw-пакетов, GPU submissions, presents и изменений изображения вести отдельно. Повтор старого кадра не считать новым отрендеренным игровым кадром.
- Этот план реализует первую картинку, корректность и 4K. DLSS/FSR/FG, RT/PT/RR, интерполяция 120–240 FPS, полный ввод, звук, фильмы и лаунчер сохраняются в общем проекте как следующие этапы.

## Текущие факты и неизвестное

- Runtime-проверка: 20 секунд, около 1199 таймерных ретрейсов, 13 открытий файлов и 15 чтений; GX вывод отбрасывается в `FifoSink`.
- Это доказывает запуск runtime и чтение ресурсов. Работу игрового цикла, логотип Capcom и title screen необходимо подтвердить визуально и реальными draw/finish событиями.
- 145 имён `gx.a` — кандидаты. Имена из сигнатур не являются подтверждением ABI или полноты покрытия.
- В HEAD найдены кандидаты `GXBegin` = `80284FD0`, `GXSetDrawDone` = `802848AC`, `GXDrawDone` = `80284990`, `GXCopyDisp` = `80285838`, `GXCopyTex` = `80285974`, `GXCallDisplayList` = `80288684`. Callback setter ещё предстоит идентифицировать. Это адреса-кандидаты, не готовые HLE mappings.
- `op_stfs` уже достигает `wr32` через `wrf32`; `wrf64` делит MMIO на две u32-записи. Задача 2 проверяет правильность размеров/порядка и границ; не переписывает работающие helpers ради другой структуры.
- Главные неизвестные: встроенные FIFO-записи, display lists, native завершение GXSetDrawDone, EFB copies и реальные текстурные/TEV состояния.
- Ортографическая проекция не доказывает принадлежность draw к HUD. Разделение scene/UI и motion vectors требует дополнительного аудита; нельзя включать DLSS на выдуманных данных.

## Review Focus

1. Guest memory изменилась после передачи draw: опубликованный пакет остаётся неизменным — тест задачи 3.
2. GXBegin с некорректным числом/форматом атрибутов или неверным индексом: ошибка с адресом, без чтения за границей — задачи 2–3.
3. Повтор completion, незавершённый GXDrawDone и close/minimize: один callback, пробуждение ожидающего потока либо явная отмена — задачи 4 и 7.
4. Текстура обновилась по тому же адресу или использует TLUT: показывается новая версия, не устаревший cache hit — задача 5.
5. 4K/resize меняет глубину, scissor, winding или EFB copy: геометрия и порядок проходов сохраняются — задачи 6–8.

- [ ] Записать gate: PASS — применяемые draw/state/copy пути перехватываются на уровне вызовов и атрибутов; PARTIAL — точный список пробелов с адресами. ### Задача 3. Нативное GX состояние, вершины, неизменные draw-пакеты

**Files:** `runtime/hle/gx.cpp`, `renderer/gx_state.*`, `gx_vertices.*`, `gx_packets.*`, `tests/test_gx_vertices.cpp`, `tests/test_gx_packets.cpp`, `project/hle_map.txt`, `tools/hle_cfg.py`.

**Interfaces:** namespace `uc::gx`; `void begin(uint8_t primitive, uint8_t vat, uint16_t count)`; `void write_attribute(std::span<const std::byte> bytes)`; `uint64_t seal_batch()`; `FramePacket` owns state, vertices, indices, texture upload bytes and completion serials. State belongs to the currently executing guest producer; GPU resources belong to consumer.

- [ ] RED: indexed/direct attributes, matrix indices, quantized signed/unsigned values, two VAT formats, triangle strip/fan/quads winding. Known three-vertex fixture produces precisely three native vertices and expected indices.
- [ ] RED: truncated primitive, excessive count, invalid array pointer/stride/index and mismatched attribute layout fail with guest address and expected/received bytes.
- [ ] RED: overwrite guest vertex/texture arrays after packet publication; consumer still sees original content. Two guest producers cannot interleave an unfinished primitive or mix state snapshots.
- [ ] Implement validated GX thunks using task 1 ABI, copying only data consumed by a draw. Preserve SDK shadow state for translated getters/internal readers, or replace those readers consistently.
- [ ] Finish primitive by descriptor-derived byte count and vertex count. GXEnd may be inline or empty; never require a separately called function that the binary lacks.
- [ ] Limit queue to two outstanding packets using mutex/condition variable. Submission/wait methods execute on guest owner/scheduler-safe boundary; avoid blocking the sole guest baton before a needed completion can arrive. Bounded errors/cancellation are visible.
- [ ] GREEN: fixture conversion, FIFO-attribute capture and queue tests. Unclassified state bytes outside a primitive are logged/countable; every observed byte needs an explicit owner before first-picture acceptance.

**Deliverable:** C++ native draw-packets; vertex bytes are data, no CPU opcode execution or general GX command interpreter.

Remove normal timed ExitProcess and detached lifetime hazards from this path; fatal crash handling remains separate.
