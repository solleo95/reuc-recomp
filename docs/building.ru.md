## Как устроена сборка

Порт — это *статическая рекомпиляция*: транслятор читает программу игры для PowerPC (`main.dol`) и пишет для неё исходный код на C++, который компилируется вместе со средой исполнения (память, потоки, Wii SDK, замещённый нативным кодом), рендерерами Vulkan и DirectX, лаунчером и платформой модов.

Из этого следует два вывода:

- **Нужна ваша собственная копия игры**, распакованная с диска: сборка читает `game\DATA\sys\main.dol`. Распакуйте свой образ `RBUE08` (NTSC-U) с помощью Wit, как описано в разделе [Установка](../README.ru.md#2-распакуйте-образ-игры-в-лаунчере-или-с-помощью-wit). Другие регионы не работают.
- Транслированный код записывается в `generated\` (исключено из git). Он получен из кода игры: никогда не коммитьте его, не публикуйте и не прикладывайте к issues или pull request'ам.

## Что понадобится

| Инструмент | Примечание |
|---|---|
| Windows 10 / 11, 64-разрядная | Порт работает только на Windows |
| **Visual Studio Build Tools** (или Visual Studio) с рабочей нагрузкой **«Разработка классических приложений на C++»** | Среда MSVC, Windows SDK, компилятор ресурсов |
| **LLVM** с `clang-cl` | Проект собирается `clang-cl` |
| **CMake** 3.25 или новее | |
| **Ninja** | |
| **Python** 3.10 или новее | Скрипты сборки и тестовый стенд (`python` должен быть в `PATH`) |
| **Vulkan SDK** | Должна быть задана `VULKAN_SDK`, в SDK должен быть `slangc` (компилятор шейдеров) |
| Доступ в Интернет при первой конфигурации | CMake скачивает закреплённые SDK NVIDIA Streamline и AMD FidelityFX и некоторые библиотеки (SHA-256 проверяется) |
| Ваша распакованная игра | `...\game\DATA\sys\main.dol` |
| Совместимая видеокарта | Vulkan 1.3, DirectX 11.1 с логическими операциями или DirectX 12 с Shader Model 6.0 и логическими операциями. GPU-тестам нужен выбранный API. См. [поддержку DirectX](directx.md). |

`scripts\env.bat` находит всё перечисленное (вызывает `vcvars64.bat`, ищет `clang-cl`, `cmake`, `ninja` и Vulkan SDK) и сообщает, чего не хватает.

## Пошаговая инструкция

1. Склонируйте репозиторий:

   ```powershell
   git clone https://github.com/solleo95/reuc-recomp.git
   cd reuc-recomp
   ```

2. Создайте `local.env` по шаблону и отредактируйте его:

   ```powershell
   copy local.env.example local.env
   notepad local.env
   ```

   Единственная обязательная строка — `UC_INSTALL_DIR`: папка, где установлена игра. В ней должен лежать `game\DATA\sys\main.dol` (распакованный диск). Готовая сборка копируется в эту папку рядом с `game\`, и в неё можно сразу играть. `local.env` исключён из git и содержит только пути вашего компьютера. Переменная, уже заданная в оболочке, важнее файла. Остальные переменные необязательные, для инструментов разработки; см. комментарии в [`local.env.example`](../local.env.example).

3. Запустите сборку из обычного терминала Windows (PowerShell или `cmd`):

   ```powershell
   .\build.bat
   ```

   Она выполняет шесть шагов: проверяет файлы игры, настраивает и собирает транслятор, транслирует игру (кэшируется по хэшу `main.dol`, транслятора и конфигурации), собирает всё и запускает тесты, раскладывает результат в `dist\` и копирует `dist\` в `UC_INSTALL_DIR`. Первая сборка занимает много времени (трансляция, линковка с ThinLTO); следующие инкрементальные.

4. Запустите `uc_launcher.exe` из папки установки.

## Команды сборки

| Команда | Что делает |
|---|---|
| `build.bat` | Полная сборка, тесты, раскладка в `dist\`, копирование в `UC_INSTALL_DIR` |
| `build.bat --no-install` | То же без копирования (транслятор, сборка, тесты, раскладка в `dist\`) |
| `scripts\dev.bat` | Сборка и тесты только в `build\` (без трансляции и раскладки) |
| `scripts\bringup.bat [аргументы uc.exe]` | Трассировочная сборка в `build-trace\` и короткий запуск (для разработки) |
| `build-release.bat` | Чистый релизный архив, см. [Сборка релизного архива](#сборка-релизного-архива) |

Результаты сборки: `build\` (дерево сборки и журналы: `configure.log`, `translator_build.log`, `translate.log`), `dist\` (разложенная игра), `generated\` (транслированный код). Всё это исключено из git.

**Журналы и отладочные файлы.** Сборка из исходников пишет журналы сессий и отчёты о падениях в `logs\`, а отладочные файлы в `debug\` рядом с `uc.exe` и `uc_launcher.exe`. Установленный релизный клиент (тот, у которого рядом с исполняемыми файлами лежит `release.json` — манифест обновлений) не пишет ничего из этого; исполняемый файл тот же, для `build-release.bat` второй сборки не нужно. Игрок включает журналы флажком «Включить логи» на первой вкладке лаунчера (`"logs": true` в `config.json`): лаунчер передаёт игре `UC_LOGS=1`, а собственный журнал лаунчера пишется со следующего запуска. Для разработчика достаточно переменной окружения `UC_LOGS=1` перед запуском. При жалобе на производительность в папке сессии лежат `frames.csv` (строка на каждый показанный кадр: время кадра, время GPU по проходам, гостевые потоки, чтения диска, текстуры) и `runtime.log`: строки `[hitch]` называют главного виновника каждого кадра, заметно более медленного обычного (`gpu`, `guest-cpu`, `guest-idle`, `present-wait`, `driver-submit`, `render-thread`, `renderer-waits-guest` или `unattributed`), строки `[dvd] open` показывают, какие файлы этапа или ролика игра загружала в это время (каждая строка `[hitch]` и `[hitches]` заканчивается последними открытыми `script=`, `room=` и `movie=`), строки `[pipeline]` показывают компиляцию шейдеров и пайплайнов на всех рендерерах (Vulkan, DirectX 11 и 12), а раз в секунду `[process]`, `[memory]` и `[vram]` сообщают об ОЗУ, загрузке процессора и видеопамяти относительно бюджета.

## Тесты

```powershell
ctest --test-dir build --output-on-failure
```

`build.bat` уже запускает их. Тесты охватывают транслятор, среду исполнения, рендерер, лаунчер, обновлятор, сеть и платформу модов. Некоторым GPU-тестам нужна видеокарта с Vulkan.

**Живые тесты игры.** `uc.exe` управляется тестовым стендом без какого-либо ввода с клавиатуры и мыши (см. [docs/testing/test-server.md](testing/test-server.md)):

```powershell
cd scripts
python -m uctest run train_gameplay --speed 8
```

Стенд копирует ваши сохранения в `build\autotest\<запуск>\saves` и никогда не играет на настоящих. Он всегда использует окно 1280x720; не запускайте тесты в полноэкранном режиме. Изменения производительности сравнивайте детерминированным демо-бенчмарком (`python -m uctest bench`), а не одним замером FPS; правила описаны в [CONTRIBUTING.ru.md](../CONTRIBUTING.ru.md).

## Структура проекта

| Папка | Содержимое |
|---|---|
| `tools/translator`, `common/analyzer`, `common/ppc` | Транслятор PowerPC в C++ и его анализ |
| `runtime` | Среда исполнения игры: память, потоки, замены SDK (HLE), звук, файловая система DVD |
| `renderer` | Рендереры Vulkan, DirectX 11 и DirectX 12, апскейлеры, генерация кадров, эффекты, трассировка лучей |
| `game` | `uc.exe`: запуск, окно, ввод, внутриигровое меню |
| `launcher` | `uc_launcher.exe`: настройки, назначение клавиш, лобби мультиплеера, обновления |
| `updater` | Изолированный обновлятор |
| `modding` | Платформа модов: Lua, JavaScript, нативные DLL, API игры |
| `mods-examples` | Примеры модов |
| `project` | Конфигурация транслятора и данные сигнатур |
| `scripts`, `tools` | Скрипты сборки, тестовый стенд (`scripts\uctest`) и инструменты разработки |
| `tests` | Модульные, интеграционные и сквозные тесты |
| `docs` | Документация, заметки о дизайне и измерения |

## Сборка релизного архива

`build-release.bat` запрашивает версию `X.Y.Z`, запускает `build.bat --no-install`, устанавливает результат в чистую временную папку и создаёт `UC-Windows-X.Y.Z.zip` и `dist-release\` (с `release.json` — манифестом обновления). Подробности и шаги публикации на GitHub: [docs/releasing.md](releasing.md).

## Если что-то не получается

- **`UC_INSTALL_DIR is not set`** — создайте `local.env` (шаг 2) или задайте переменную в оболочке.
- **`main.dol not found`** — нет файла `UC_INSTALL_DIR\game\DATA\sys\main.dol`. Распакуйте туда образ игры с помощью Wit.
- **`clang-cl not found`, `ninja not found`, `VULKAN_SDK is not set`, `slangc.exe not found`** — установите инструмент и откройте новый терминал, чтобы обновились `PATH` и `VULKAN_SDK`.
- **Конфигурация падает при скачивании SDK** — проверьте подключение к Интернету и что прокси не блокирует `github.com`; запустите ещё раз.
- **Сборка или тест падает** — прочитайте журналы в `build\` (`configure.log`, `translator_build.log`, `translate.log`) и вывод `ctest --output-on-failure`. Если считаете, что это ошибка проекта, создайте [issue](https://github.com/solleo95/reuc-recomp/issues) с журналом, но не прикладывайте файлы игры и содержимое `generated\`.
