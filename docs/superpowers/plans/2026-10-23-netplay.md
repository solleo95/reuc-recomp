# Direct-IP Coop Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Track checked tasks here; no commits requested.

**Goal:** Two launcher peers become ready, launch once, and play original coop over IP.
**Architecture:** TCP lobby followed by a game connection on the same port; startup barrier and deterministic input lockstep with independently mapped P1/P2 actions.
**Tech Stack:** Existing C++20, Winsock, SDL3/ImGui, CTest and Python uctest.
**Spec:** ../specs/2026-10-23-netplay-design.md

## Global Constraints
- Use current clean feat/multiplayer checkout. No commits or pushes.
- Harness only; muted 1280x720 windows, fps-limit 0, copied saves/config.
- Validate bounded network messages; timeouts/cancel; no detached network threads.
- Preserve single-player behavior and existing demo format.

## Review Focus
- Partial TCP reads, invalid lengths, invalid pad values: reject safely.
- One ready participant or repeated ready packet: never double launch.
- Peer exits during startup or game: abort boundedly and release inputs.
- P2 native actions: target P2 actor, independent of P1 state.
- Divergent startup data/settings: refuse before the first input frame.
