## 1. Результат для игрока

| Действие | Назначения по умолчанию | Поведение |
|---|---|---|
| Взаимодействие | ЛКМ | Подбор предмета, выбор пути и другие штатные действия; удержание также включает исходные сочетания |
| Выстрел | ПКМ | Одиночный выстрел/удержание по правилам текущего оружия |
| Предыдущее оружие | Колесо вверх, W | Один переход на событие; пропуск недоступного оружия |
| Следующее оружие | Колесо вниз, S | Один переход на событие; пропуск недоступного оружия |
| Перезарядка | R | Штатная анимация, длительность, ограничения и расход боезапаса |
| Граната | G; удержание взаимодействия + нажатие выстрела | Один штатный бросок; сочетание по умолчанию соответствует ЛКМ+ПКМ |
| Нож | Удержание V; движение мыши при удержании взаимодействия | V повторяет горизонтальный взмах слева направо, 90°, со штатным интервалом; мышь выбирает направление исходного взмаха |
| Пауза | Esc | Штатная пауза в геймплее |
| Подтверждение меню | ЛКМ, Enter | Подтверждение только в соответствующем контексте |
| Назад в меню | ПКМ, Esc | Возврат только в соответствующем контексте |
| Освобождение курсора | Alt | Действует только в Windowed; fullscreen сохраняет захват |
| Скриншот | Ctrl+E | Существующий снимок в папку debug; отдельный служебный бинд |

E сама по себе свободна. Направление колеса/W/S — выбранное здесь попарное соответствие; допускается переназначение.

Наведение остаётся сырым относительным вводом без ускорения/сглаживания. Удержание взаимодействия разрешает ножевые движения мышью; обычное наведение без этого удержания не создаёт взмах. V не требует движения мышью. Точное представление направления/дуги в игровом обработчике проверяется по коду и реальному удару, а не подстановкой произвольного угла в неизвестное поле.

## 2. Бинды и сочетания

Каждое действие имеет собственный список назначений; можно добавлять несколько клавиш/кнопок, удалять отдельную запись и нажать **«Очистить все»** для этого действия. Пустой список означает, что действие не назначено; он сохраняется пустым после перезапуска. Отдельная команда восстановления стандартной раскладки возвращает значения из таблицы.

Поддерживаются клавиши клавиатуры с различением левых/правых модификаторов и основного блока/NumPad, кнопки мыши, оба направления колеса и комбинации модификатора с клавишей/кнопкой. Хранится физическая клавиша SDL scancode, а отображаемое имя определяется раскладкой пользователя; хоткеи не зависят от вводимого текстового символа.

Исходные сочетания представлены отдельными назначениями:
- «Удержание взаимодействия + нажатие выстрела» в строке гранаты;
- «Направленное движение мыши при удержании взаимодействия» в строке ножа.

Они следуют назначенным действиям при переназначении ЛКМ/ПКМ. Их можно отдельно удалить; «Очистить все» для гранаты/ножа удаляет и обычные, и эти сочетания. Исходная комбинация не остаётся скрытым активным биндом после очистки.

Held действия — объединение всех удерживаемых назначений: отпускание одной кнопки при удержании другой не отпускает действие. Изменение биндов сбрасывает старые удержания; новый набор не создаёт неожиданный выстрел от уже зажатой кнопки. Потеря фокуса освобождает удержания и отменяет ожидающие игровые команды.

События обрабатываются в порядке поступления. Нажатие выстрела при уже удерживаемом взаимодействии выбирает гранату и подавляет обычный выстрел этого события. Удержание сочетания не создаёт поток гранат. G и сочетание, попавшие в одно обновление, дают один запрос броска. Ножевые запросы V/мыши также проходят один штатный ограничитель частоты. При одновременных ножевых источниках направленный жест выбирает направление для следующего разрешённого удара; V служит горизонтальным вариантом при отсутствии жеста.

Рекомендованные конфликты между разными действиями показываются в лаунчере явно; назначение не перезаписывает другую строку. Одинаковая кнопка в разных игровых контекстах допустима. Связи сочетаний ограничены двумя перечисленными случаями; произвольный язык макросов не вводится.

## 3. Нативная граница

SDL на основном потоке публикует реальные host-события. Нативный резолвер превращает их в Aim/Interact/Fire/Reload/WeaponPrevious/WeaponNext/Grenade/Knife/Pause и команды меню. Игровой поток принимает их под существующим scheduler baton. Поток SDL не пишет в игровую память и не вызывает функции игры.

Для обычных кнопок используются уже проверенные границы потребителей ввода. Для Reload/Knife и motion-QTE распознавание жеста заменяется в проверенном игровом контексте настоящим запросом ПК. Штатная логика проверяет доступность действия, боезапас, анимацию, cooldown и результат попадания. Никакого искусственного ускорения WiiMote, радиопротокола, аппаратной модели, JIT или исполнения инструкций из образа в рантайме.

Контекст меню/геймплея/QTE берётся из проверенного состояния игры. FPS, время с запуска и координаты мыши не служат признаком контекста. QTE сохраняют временное окно и необходимость ввода; соответствующие команды кнопок/сочетаний/движения показываются через новые подсказки. Автоматического успеха QTE нет.

Уточнение владельца2026-10-14: motion-QTE должны поддерживать резкие движения мышью без зажатия дополнительных кнопок. Это отдельное переназначаемое/очищаемое назначение, активное только в подтверждённом motion-QTE; обычный нож по-прежнему требует удержания взаимодействия. Распознавание использует реальные смещения и время host-событий; порог и отмена проверяются независимо от render FPS. Native граница учитывает реальные жесты через исходный счётчик/таймер QTE, сохраняет промахи и истечение времени. Точные callsites и поля подтверждаются до подключения; искусственные IMU-сэмплы не вводятся.

Доказательства и кандидаты: `docs/spikes/I0-native-actions-feasibility.md`. Адреса нового HLE разрешены только после подтверждения назначения. Статический оригинальный DOL и наблюдение инициализированного игрового состояния используются совместно. Текущий профиль — RBUE08; другие регионы/ревизии требуют собственных проверенных AOT-профилей. Ghidra остаётся отложенной по `docs/decisions.md`.

## 4. Конфигурация и лаунчер

Сохранение — секция `input` в предусмотренном проектом `config.json` рядом с exe, с версией схемы, стабильными именами действий и списками типизированных назначений. Общая модель/загрузка используются игрой и лаунчером. Отсутствующий input-раздел выбирает стандартную раскладку; пустой список отдельного действия сохраняет очистку. Неизвестная версия, неверные значения, дубли свойств/назначений и слишком большие списки дают объяснимую ошибку; существующий файл не перезаписывается автоматически.

Лаунчер Dear ImGui/SDL3 сохраняет существующие поля запуска из основной спеки и добавляет вкладку **«Управление»**: список действий, все текущие бинды, «Добавить», удаление отдельной записи, «Очистить все», восстановление стандартной раскладки. Захват бинда происходит только в активном лаунчере; Esc отменяет захват, подтверждение зарезервированной клавиши остаётся доступным явным способом. Сохранение сначала валидирует весь документ, затем атомарно заменяет файл; ошибка записи сохраняет прежний файл и текущую игровую конфигурацию.

Внедрение JSON/ImGui использует уже выбранную архитектуру лаунчера; конкретные зависимости и версия фиксируются в отдельном плане лаунчера после проверки локального окружения. Парсинга, выделения строк и дискового I/O в игровом цикле нет. Эта работа не меняет ещё не реализованные DLSS/FSR-настройки на фиктивно работающие.

## 5. Подсказки на стороне порта

Порт рисует собственные иконки ЛКМ/ПКМ/дополнительных кнопок мыши, колеса вверх/вниз и клавиш клавиатуры. Иконка клавиатуры содержит актуальное имя клавиши; поддерживаются модификаторы, функциональные клавиши и NumPad. Сочетания имеют понятный знак «+», жест ножа — направление движения и удерживаемое действие. V показывает горизонтальный взмах. Несколько биндов отображаются как альтернативы; длинный список укладывается/переносится без выхода за границы подсказки. Пустой список показывает **«Не назначено»**.

Источник подсказки — семантическое действие и текущий контекст, а не жёстко заданная буква Wii. После переназначения обновляется и подсказка. Профиль идентифицирует конкретную игровую UI-подсказку/панель на нативной границе; только её изображение/лейбл заменяется в host DrawPacket. Глобальная подмена общей игровой текстуры/атласа запрещена: она может изменить посторонние элементы.

Иконки и текст принадлежат порту и рисуются с достаточным разрешением для выбранного вывода. Путь screenshot должен включать тот же итоговый UI, что видит игрок. Ни один файл `game/DATA` не изменяется; исходные текстуры, шрифты, локализация и файлы сохранений остаются данными пользователя. Неподтверждённая подсказка сохраняет исходный вид, регистрируется как непокрытая; полная замена всех промптов не заявляется до проверки меню, обучения и QTE.

## 6. Порядок и проверка

Три самостоятельных этапа: (1) нативные действия и общая модель биндов; (2) сохранение и полноценная вкладка лаунчера; (3) замена игровых подсказок на host UI. Каждый имеет отдельный план и критерий завершения. Конкретный план этапа1 составляется после проверки этого дополнения.

Проверка включает короткие клики, несколько удерживаемых биндов, порядок сочетаний, фокус, независимость колесика/W/S, восстановление/очистку, ошибочный config, real Reload/Knife/Grenade и QTE. Видимая диагностическая игра со звуком, --skip-intro и копией сохранений управляется только внутри собственного процесса. Состояния боя, анимация, боезапас и результат попадания подтверждаются реальным прогоном. GPU-проверка UI охватывает изменение размера, fullscreen, высокое разрешение, альфа-смешивание и совпадение скриншота/вывода.

Сборка — `dist`, установка — `<install dir>` через `/E`; файлы и планы не удаляются. Коммиты только по запросу. Новые временные ограничения записываются в `docs/tech-debt.md` в том же изменении. Непроверенные семантические функции не заменяются предположениями.
