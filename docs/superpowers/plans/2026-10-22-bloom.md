# Bloom replacement Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the game's half-resolution bloom with a six-level float bloom (owner's "variant 5") that looks right in SDR and in HDR10, with an on/off checkbox and a 0..200 % strength slider.

**Architecture:** A `BloomPass` (compute, `renderer/bloom_pass.{h,cpp}`, `renderer/shaders/bloom.slang`) runs at the scene boundary after the upscaler, motion blur and DLSS 5 hook and before the HUD, on the output-size EFB colour. It builds an RGBA16F pyramid (Karis-weighted first downsample, tent upsample, six weighted levels) from an inverse-tone-expanded copy of the scene. SDR: the glow is added to the EFB in place (gamma 2.2, static dither). HDR: the glow stays in a per-slot float image that `hdr.slang` adds in nits at the HDR encode (present and frame generation's HUD-less copy), so it can pass paper white up to the peak. The game's composite draw (`gx::bloom_composite`) is always skipped.

**Tech Stack:** C++20, Vulkan 1.3 compute, Slang → SPIR-V, existing `PassTimer` / options plumbing / `renderer_effects_smoke`.

**Spec:** `docs/superpowers/specs/2026-10-22-bloom-design.md` (read it first: it holds the owner's decisions, the designer's calls and the starting constants).

## Global Constraints

- Settings: `graphics.bloom` (bool, true = new bloom, default true; the key's meaning does not flip, no migration), new `graphics.bloom_strength` integer 0..200 (default 100, out of range refused like the other config values); CLI `--no-bloom` unchanged, new `--bloom-strength N`; both live in the launcher Graphics page and the in-game menu (Insert), applied live, 13-language strings in `launcher/translations.inc`.
- Strength 0 equals bloom off exactly. Off = no bloom at all (the game's composite stays skipped in every case).
- Starting constants (spec): level weights 0.20 / 0.20 / 0.18 / 0.16 / 0.14 / 0.12 for levels 1..6, additive mix `0.15 × strength` in SDR and `0.15 × 2.5 × strength` in HDR, no threshold, inverse expansion knee 0.6, SDR headroom 4, HDR headroom peak/paper. Level `i` = scene-target size >> (i+1). Tuned by eye in the game afterwards; acceptance is the owner's eye.
- SDR composite: gamma 2.2 (as `hdr.slang`, not piecewise sRGB), ±0.5 LSB static ordered dither. Deterministic runs (`--deterministic`, demos, `det_check`) stay bit-identical: no temporal state, no per-frame noise.
- Frame without a scene boundary (menus, movies, black frames): no bloom that frame, and no stale glow sampled from an earlier frame.
- HDR glow may overlap the HUD (owner option A). Option B (separate scene/HUD layers) is NOT built.
- Source edits with Edit/Write only (no shell heredoc/sed patches). Build `build.bat --no-install`; tests `ctest --test-dir build --output-on-failure`. Never run tests fullscreen (harness forces 1280x720). Commit only when the owner says so, with explicit paths (the tree already holds uncommitted HDR work).
- Budget: bloom pass ≤ 0.4 ms at 1440p on the RTX 4080 (pass timers / `--profile`).

## Review Focus

1. **Menu / movie / black frame with bloom on.** No glow: HDR encode must not read a result left in the slot from an earlier frame (Task 5 test).
2. **Windows HDR toggled, window resized or render scale changed with bloom on.** Pyramid and per-slot results are recreated, no stale descriptors, no validation errors (Task 3 smoke, Task 5).
3. **Peak below paper white.** The glow still obeys the existing clamp: output never exceeds peak (Task 4 math test).
4. **Strength slider dragged 0→200→0, checkbox toggled 20 times.** No per-frame resource creation, no hitch, 0 equals off (Task 3 smoke).
5. **Upscaler off, SMAA, DLSS, FSR and frame generation.** Same glow size relative to the screen at 1x and 4K; generated frames match real frames (Task 5 live run).

### Task 1: Bloom math and settings type

**Files:**
- Create: `renderer/bloom_math.h`
- Test: `tests/test_bloom_math.cpp` (+ `tests/CMakeLists.txt`, mirror the `test_hdr_math` entry)

**Interfaces:**
- Produces (namespace `uc`, header-only):
  - `struct BloomSettings { bool enabled=true; uint32_t strength=100; bool operator==(const BloomSettings&) const=default; };`
  - `inline constexpr uint32_t kBloomStrengthMax=200;` `inline bool valid_bloom_settings(const BloomSettings&)`
  - `inline constexpr float kBloomKnee=.6f, kBloomSdrHeadroom=4.f, kBloomBaseMix=.15f, kBloomHdrGain=2.5f;` `inline constexpr std::array<float,6> kBloomWeights{.20f,.20f,.18f,.16f,.14f,.12f};`
  - `inline float bloom_expand(float v, float headroom)` — `v` linear 0..1 → scene-referred (1.0 = paper white): `v` up to the knee, above it `v + ((v-knee)/(1-knee))² × (headroom-1)`.
  - `inline float bloom_mix(const BloomSettings&, bool hdr)` — 0 when disabled, else `strength/100 × kBloomBaseMix × (hdr ? kBloomHdrGain : 1)`.
  - `inline float bloom_karis_weight(float luma)` = `1/(1+luma)`.
  - `struct BloomLevel { uint32_t width, height; }; inline BloomLevel bloom_level_extent(uint32_t width, uint32_t height, uint32_t level)` = `max(1, size >> (level+1))`, level 0..5.

### Task 3: BloomPass (pyramid, SDR composite, HDR glow image)

**Files:**
- Create: `renderer/bloom_pass.h`, `renderer/bloom_pass.cpp`, `renderer/shaders/bloom.slang`
- Modify: `renderer/CMakeLists.txt` (shader build entries like `hdr.slang`, `bloom_pass.cpp` in `uc_vulkan`, `UC_SHADER_FILES`), `renderer/pass_timer.h` (`GpuPass::bloom`, before `count`), `renderer/renderer_effects_smoke.cpp` (new `--bloom` section)

**Interfaces:**
- Consumes: Task 1 constants/functions (the shader mirrors the math, as `hdr.slang` mirrors `hdr_math.h`); `UpscaleImage` (`renderer/upscaler.h`), same initialize/idle/`make_image` conventions as `OcclusionPass`.
- Produces:
  - `struct BloomInputs { VkCommandBuffer command; UpscaleImage color; /* output-size EFB colour, RGBA8, storage usage, GENERAL, modified in place when !hdr */ VkExtent2D region; /* scene part of the target */ BloomSettings settings; bool hdr; float hdr_headroom; /* peak/paper */ uint32_t slot; uint64_t targets_generation; };`
  - `class BloomPass { void initialize(VkDevice, const VkPhysicalDeviceMemoryProperties&, const std::filesystem::path& shaders, uint32_t slots, std::function<void()> idle={}); void record(const BloomInputs&); VkImageView glow_view(uint32_t slot) const; bool glow_valid(uint32_t slot) const; void invalidate(uint32_t slot); void shutdown(); };`
  - Contract: `record` with `hdr=false` composites into `color` and leaves `glow_valid(slot)` false; with `hdr=true` writes the scaled glow (`bloom_mix(settings,true) ×` pyramid sum, scene-referred, 1.0 = paper white) into the slot's RGBA16F image (extent = `color` extent), sets `glow_valid(slot)` true, leaves `color` untouched. `strength 0` or `!enabled` records nothing and invalidates the slot.

- [ ] **Step 2: Run** `renderer_effects_smoke.exe --bloom --validation` from `build/renderer` (with `VK_LOADER_LAYERS_DISABLE=~implicit~`). Expected: FAIL.
- [ ] **Step 3: Implement** `bloom.slang` with three compute entry points: `downsample` (level 0 reads the colour through `bloom_expand` in linear light with the Karis-weighted 13-tap, later levels plain 13-tap), `upsample` (tent, accumulating `weight × level` back up), `composite` (SDR only: decode gamma 2.2, add glow, encode, static 4×4 ordered dither ±0.5 LSB, write RGBA8). Pyramid images RGBA16F sized by `bloom_level_extent` of `color`'s extent; recreate on size or `targets_generation` change after `idle()`; one glow image per slot, allocated on the first `hdr=true` record.
